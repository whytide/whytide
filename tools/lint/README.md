# tools/lint: the structural lint

`pnpm lint` fails on the structural mistakes the rules forbid, so no reviewer catches them by eye: a module importing another module's internals, a framework in `domain/`, a vendor SDK outside its adapter, Mastra outside `core/packages/ai` or its Enterprise Edition code anywhere, a literal string in a screen, a raw `fetch`, a `TODO` without a task. The rules come from [coding §2, §4, §6](../../docs/rules/coding.md#2-boundaries), [security §5](../../docs/rules/security.md#5-requests-uploads-and-egress) and [architecture §4.3, §9, §17](../../docs/architecture.md#43-how-modules-talk).

## Running it

| Command | What it does |
|---|---|
| `pnpm lint` | every package, through `pnpm -r --if-present lint` |
| `pnpm -F <name> lint` | one package or module, for example `pnpm -F contacts lint` |
| `node tools/lint/lint.ts [paths...] [--fix]` | the paths given (files or folders; `core/` and `ee/` when none), from anywhere in the workspace |

A finding prints as `path:line:column rule message`, paths relative to the repository root; the exit code is 1 when a finding remains. `--fix` applies the fixes the rules offer and reports the rest. Build outputs, `node_modules`, generated files and `core/modules/_template` are never checked. An import written as a path into `node_modules` (`../../node_modules/axios/index.js`, or an absolute path through `.pnpm`) is read as the package it reaches (`axios/index.js`), for every rule, once the path is normalized (`./`, `../` and a doubled `/` resolved). A `file:` URL is first read as the path Node loads, escapes decoded (`%40mastra` is `@mastra`); one Node cannot load, a malformed escape for one, stops the lint.

The linter is `@whytide/lint`, a workspace package with no dependencies of its own: it parses with the TypeScript compiler API already in the tree and Node 26 runs its files directly. `pnpm -F lint typecheck` type-checks it, `pnpm -F lint test` runs the fixtures.

## The rules

| Rule | Protects | Fix |
|---|---|---|
| `module-boundaries` | A file in a module imports another module only as `@whytide/<name>`, which resolves to its `index.ts`; never that module's `domain/`, `api/`, `agents/`, `workflows/`, `ui/` or any other file, never a host (`core/apps/*`), except the web host's API client from the module's `ui/` (`@whytide/web/api/server`, `@whytide/web/api/browser`: its screens run in the web host only), never the Prisma client generated for another module (`core/packages/db/generated/<module>/`). A file under a module's `tests/` may also import another module's test helpers as `@whytide/<name>/testing`; no other file may. Any file under `core/` never imports `ee/`. Relative imports and `@whytide/*` imports are resolved; a package is found by its folder name under `core/modules`, `core/packages`, `core/apps` and `ee/modules`. | a relative import of another module's index becomes `@whytide/<name>` |
| `no-framework-in-domain` | A file under a module's `domain/` imports nothing from NestJS (`@nestjs/*`), Next.js (`next`, `next/*`), Prisma (`@prisma/*`, `prisma`), Temporal (`@temporalio/*`) or Mastra (`@mastra/*`, `mastra`). | |
| `vendor-sdk-in-adapter-only` | A package listed in [`vendor-sdks.json`](vendor-sdks.json) is imported only inside its adapter folder; everything else reaches the vendor through the port. | |
| `mastra-in-ai-only` | `@mastra/*` and `mastra` are imported only under `core/packages/ai/`, which sets Mastra's guard (`MASTRA_OFFLINE`, `MASTRA_TELEMETRY_DISABLED`) before any Mastra import; a module's `agents/` declares its tasks with `@whytide/ai`. Mastra's Enterprise Edition code is imported nowhere, `core/packages/ai/` included: a path with an `ee` segment under `@mastra/` (`@mastra/core/auth/ee`, `@mastra/core/agent-builder/ee`), `@mastra/core/auth` and every path under it (it re-exports most Enterprise exports under other names: `StaticRBACProvider`, `checkFGA`, `validateLicense`, …), `@mastra/core/license`, and any path into a Mastra package's build (`@mastra/<package>/dist/…`), where the Enterprise code also sits in chunks whose names have no `ee` segment (`dist/ee-btY6vXIW-DKf_xOxH.js`). Why: that code is under the Mastra Enterprise Edition License, which is not open source (no production use without a key, no redistribution, no hosted service), and the owner accepted Mastra on 2026-10-22 on condition that our code never uses it (docs/15 §14, rule 7, in the planning repository). | |
| `no-literal-strings-in-screens` | Under a module's `ui/`, under `core/packages/ui/` and under the web host's `app/` and `src/`: JSX text that is not only whitespace, a string literal as a JSX child, and a string prop that holds words (whitespace inside, a capitalized word, or `.`, `!`, `?`, `:` at the end) are findings. Exempt props: `aria-*`, `data-*`, `className`, `href`, `key`, `id`, `testId`, and the token-valued HTML attributes (`type`, `role`, `rel`, `src`, `name`, `target`, `htmlFor`, `lang`, `dir`, `method`, `action` and a few more, listed in the rule). A single lower-case word (`variant="primary"`) passes as a token. | |
| `no-raw-fetch` | Outside `core/packages/platform/http/` and the adapter folders (`core/packages/providers/<port>/<adapter>/`, where neither name is `tests`, `testing` or starts with `_`): any reference to the global `fetch` or `WebSocket`, not only a call (`fetch.call(…)`, `const f = fetch`, `{ fetch }`, `new WebSocket(url)`, `extends WebSocket`), also through `globalThis`, `global`, `window` or `self` (`.fetch`, `["fetch"]`, `const { fetch } = globalThis`); Node's `http`, `https`, `http2`, `net`, `tls`, `dgram`, `dns` and `dns/promises` (a DNS query leaves the machine too), and the internal `_http_agent`, `_http_client` and `_tls_wrap` that Node 26 still loads, with or without `node:`, imported statically, by `import()`, `require`, a `createRequire(…)` function or `process.getBuiltinModule`, unless only `createServer`, `createSecureServer`, `Server` and types are taken from them: `http.get`, a named `get` import, `const { request } = http`, `new http.ClientRequest(…)`, `net.connect(…)` and the module passed, exported or loaded whole are findings; and any import of `axios`, `cross-fetch`, `follow-redirects`, `got`, `isomorphic-fetch`, `ky`, `needle`, `node-fetch`, `ofetch`, `superagent`, `undici` or `ws`. The list is not exhaustive: a new client package also meets the dependency review, one package per merge request. Test code has its own allowance, below. A `data:` URL module, by any loader and in any case (`import("data:text/javascript,…")`), is a finding in every file, test code and adapters included: its code can import any built-in or `file:` URL past every rule. | |
| `no-todo-without-task` | A comment containing `TODO` (any case) carries a task ID such as `alpha-p3-020`. | |
| `decrypt-in-worker-only` | The worker decrypt entry of secrets at rest, `@whytide/platform/secrets/worker` (or the files behind it by a relative path, built or not: `core/packages/platform/secrets/worker.ts` and `keys.ts`, which holds the unwrap), is imported only under `core/apps/worker/`, under a module's `workflows/`, and inside the platform's own `secrets/` and `tests/`; never from the platform's `index.ts`, so the package root exports `encryptSecret` only. A module's `workflows/`, where its own decrypt entries sit (linkedin's `withDecryptedRef`), is imported, by a relative path or `@whytide/<module>/…`, built or not, only under `core/apps/worker/` and from the module's own `workflows/` and `tests/`: never from its `api/`, `domain/` or `index.ts`, nor from the api host ([security §4](../../docs/rules/security.md#4-secrets-and-keys)). | |
| `prompt-file-header` | Every prompt file of an agent, `agents/<agent>/prompt.v<N>.md` beside its `task.ts` in a module, starts with the data-block header of [core/packages/ai](../../core/packages/ai/README.md#the-prompt-file): a line `Data blocks: <profile>, <evidence>` naming the blocks the input arrives in, then the sentence that marks them as data, never instructions ([security §6](../../docs/rules/security.md#6-ai)). The linter reads code files only, so the rule runs on each `agents/<agent>/task.ts` and reads its folder through `LintFile.readFolder`; the finding sits on `task.ts` and names the prompt file. A prompt file in an agent folder without `task.ts` is not seen. | |
| `logical-css-properties` | In a stylesheet (`.css`), a physical property or value that has a logical one, so that right-to-left languages need no rewrite ([architecture §17](../../docs/architecture.md#17-languages)): a side of `margin`, `padding`, `scroll-margin`, `scroll-padding` and `border` (its `-width`, `-style` and `-color` too), a corner of `border-*-radius`, the insets `top`, `right`, `bottom` and `left`, and the value `left` or `right` of `text-align`, `float` and `clear`; the message names the logical one (`margin-left` is `margin-inline-start`). Not seen: the four values of a shorthand (`margin: 0 1rem 0 0`), the sizes (`width` and `height`, which are `inline-size` and `block-size`), `overflow-x`, `resize`, and inline styles in TSX. The linter lists `.css` files for this rule and parses them as TypeScript only to place a finding; the other rules see what that parse makes of a stylesheet: an `@import "…"` as an import (`module-boundaries` checks it), some of its comments (`no-todo-without-task`), nothing else. | |
| `logical-utility-classes` | In a `className` (or `class`) and in the arguments of `cx`, `clsx` or `cn`, a Tailwind utility of the inline direction that has a logical one, its variants, `!` and `-` aside: `ml-`, `mr-`, `pl-`, `pr-` (and `scroll-` ones), `left-`, `right-`, `text-left`, `text-right`, `float-` and `clear-` `left` or `right`, `border-l`, `border-r`, `rounded-l`, `rounded-r` and the corners `rounded-tl`, `-tr`, `-bl`, `-br`; the message names the logical one (`ml-` is `ms-`, `rounded-tl` is `rounded-ss`). It reads the strings written there, and those of a `const` of the same file that such a place reads, itself or through a member access (`SHIMMER`, `TONES.hot`, `VARIANTS[variant]`), and so on through the consts that one reads (Badge's `TIERS`, by way of `const [badge, icon] = TIERS[tier]`). A const that a class only calls, or whose method it calls (`STACKED.has(name)`), is not read, nor one named outside a class. The stylesheet rule above is its twin. Not seen: a class string imported from another file, held in a `let` or a parameter, or returned by a function, and the block direction (`mt-`, `top-`), which Tailwind has no logical utility for. | |
| `workflow-input-ids-only` | An object schema under a module's `workflows/` (`z.object`, `z.strictObject`, `z.looseObject`, `.extend`, `.safeExtend`) has no field named in the PII registry (`email`, `name`, …, from `core/packages/platform/logging/pii.ts`) or after a column marked `/// pii` in `core/packages/db/prisma/schema` (its field or its `@map` name, in camelCase and snake_case): workflow and activity inputs carry ids only, since Temporal keeps them in its history ([architecture §8](../../docs/architecture.md#8-background-work-temporal-and-mastra)). The rule reads the schema folder through `LintFile.readFolder`. Not seen: a field added another way (a spread, a computed key, `z.record`) and an activity's output. | |

Test code and `no-raw-fetch`: the global `fetch` and Node's network modules are allowed in the `tests/` of a package, a module or a host (`core/<apps|modules|packages>/<name>/tests/`, the same under `ee/`), and in a port's `tests/`, test helpers (`core/packages/providers/<port>/testing/`) and contract suite (`<port>/contract.ts`). A `tests/` folder anywhere else, such as a Next.js route segment, gets no allowance, and an adapter's own tests sit in its adapter folder. A test reaches its own server on 127.0.0.1 or the stack's Mailpit with them, never a vendor ([coding §11](../../docs/rules/coding.md#11-tests)). The allowance goes by path, not by who imports the file: a fake adapter imports `contract.ts` too (`app-mail/fake` takes `asRead` from it), so that code can run in a host. `WebSocket` and the client packages stay findings in test code, and a port's `tests/` and `testing/` are not adapter folders.

What the rules do not see: a type-only or ambient reference that is not an import; a comment inside JSX text; a literal reached through a variable (`const label = "Save"`). For `no-raw-fetch` and `mastra-in-ai-only`: a specifier computed at run time (`import(name)`), a renamed `require` or `createRequire`, `module.require(…)`, an `import x = require(…)` declaration (a `.cts` file), and code run by `eval`, `new Function`, `new Worker(code, { eval: true })` or a child process. For `no-raw-fetch`, also: the global object reached another way (`const g = globalThis`, `globalThis[name]`, `globalThis.globalThis.fetch`, `Reflect.get`) or destructured by an assignment (`({ fetch: f } = globalThis)`), and a request made inside a function that the egress client, an adapter or test code exports; the rule goes by names, not scopes, so a local named `fetch`, `WebSocket` or like an imported network module counts as one. For `decrypt-in-worker-only`: a computed specifier, and a host importing another host's file by a relative path; the platform's own root is guarded by its test too (`tests/secrets.test.ts`: the root has no `decryptSecret`). The message-key check of a later task covers the keys themselves.

## The vendor registry

[`vendor-sdks.json`](vendor-sdks.json) maps an adapter folder to the packages only it may import. An adapter task adds its entry in the same merge request as the adapter ([coding §6](../../docs/rules/coding.md#6-ports-and-adapters), rule 2):

```json
{
  "core/packages/providers/linkedin/unipile": ["unipile-node-sdk"]
}
```

## Adding a rule

1. One file under `rules/`, exporting `rule: Rule` ([`rule.ts`](rule.ts)): a name, one line on what it protects, and `check(file)`, which returns findings with a message and, when the fix is mechanical and safe, a text edit. The linter loads every file in `rules/`; there is no list to edit.
2. A fixture folder `fixtures/<rule name>/` with a `pass/` tree that must be clean and a `fail/` tree with an `expected.json` naming the rule IDs each file must produce, one entry per finding. Fixtures are mini repositories: `core/modules/a/domain/x.ts` and so on.
3. The row above and the row in the root `AGENTS.md`. `pnpm -F lint test` fails on a rule without a fixture folder and on a fixture folder without a rule.

## Why not Biome rules

Biome is the formatter ([ADR 0001](../../docs/adr/0001-formatter.md)) and its linter stays off. Its built-in restrictions see an import's text but not the importing file's path relative to another module, cannot read the vendor registry, and cannot inspect comments; its GritQL plugins have the same limits. The rules are therefore one small linter on the compiler API, as the task's design asked, instead of being split across two tools with two kinds of fixtures.
