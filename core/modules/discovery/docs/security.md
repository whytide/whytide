# discovery: security

Read this before changing the module ([security §8](../../../../docs/rules/security.md#8-conduct)).

- **Uploads** ([security §5](../../../../docs/rules/security.md#5-requests-uploads-and-egress)): one `.csv` part, with no field or second part. The file is limited to `IMPORT_MAX_BYTES` and `IMPORT_MAX_ROWS`, the whole body to twice `IMPORT_MAX_BYTES` and two minutes. busboy has no limit of its own on a body, so `api/multipart.ts` counts the bytes. At the first byte or row past a limit, reading stops and the connection closes. A ZIP signature, a NUL byte or invalid UTF-8 is refused before the parser sees the bytes.
- **No evaluation**: csv-parse runs without `cast`, `cast_date`, `on_record`, `raw` or `info`, so every cell is a string, and nothing in the module interprets a cell. `max_record_size` is 64 KiB. A row's width is bounded only by the file limit, because empty fields do not count toward it.
- **The own runs**: the upload runs outside the request's tenant run (`whytide:own-runs`). It uses the tenant the host's workspace guard resolved, `req.tenant`, never a workspace from the body or the file. Each database step is a `withTenant` run on the module's `app` client (`domain/store.ts`). The run's route claims the job in the request's tenant run, so another workspace's job is `import_not_found`.
- **The run in the worker**: discovery's subscriber takes the workspace from the delivery's tenant, `currentTenant()`, never from the event's payload, and builds the workflow's id from it. The activities run as the worker's service principal in that workspace, each step a `withTenant` run on the module's client. The workflow's input and result, which Temporal keeps in its history, carry the workspace and job ids, a code and counts: never a cell.
- **The run's writes**: persons and leads only through contacts' commands, in the run's transaction; discovery writes no contacts table. An erased person is never imported again: the file's hash check first, then contacts' own refusal (`person_erased`) at each upsert. A re-import resets no retention clock: a lead keeps its `firstSourceAt`.
- **Isolation**: the file key is built by the files port's guard under `w/<workspace_id>/`. The GET routes read through the request's tenant client. `tests/tenancy.test.ts` registers `import_jobs` in the two-workspace harness. Another workspace's job is `import_not_found`.
- **Personal data**: the stored file holds the profile URLs, names and companies of people the tester listed (docs/data.md). No log line, report or error carries a cell. The report holds record numbers and codes only; the run's counts and failure hold counts, a chunk's index and a code. `discovery.people_imported` carries ids only, and the run logs no line per row. The erased check hands the valid URLs to contacts' `isHashed` inside the upload's run; discovery never sees a hash or the salt, and another workspace's hash marks no row.
- **Who may do what**: `imports.write` uploads and runs, `imports.read` reads; both are granted to Owner, Admin and Member. A job's answer names its uploader by user id, `createdBy`, to whoever may read imports; the screen shows "You" for the viewer's own and no name for another's.
- **CSV written out**: the screen's two downloads, built in the browser as `data:` URLs: the sample, a constant of made-up rows, and a report's error rows, `row,code` lines of record numbers and the four row codes. Neither holds a cell of a file, so neither needs neutralising. An export of cells, if one ever comes, must neutralise cells that start with `=`, `+`, `-` or `@`.
