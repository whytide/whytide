# discovery: the brief for a coding agent

1. Read `README.md`, then `docs/concepts.md`, `docs/data.md`, `docs/flows.md`, `docs/security.md` and `docs/runbook.md`. They say what is true now and change in the same merge request as the behavior.
2. The rules: [coding](../../../docs/rules/coding.md), [security](../../../docs/rules/security.md), [delivery](../../../docs/rules/delivery.md). The shape of this folder is [architecture §4.2](../../../docs/architecture.md#42-inside-a-module): rules in `domain/` without a framework, Zod schemas in `schemas/`, NestJS in `api/`, Temporal in `workflows/`, agent tasks in `agents/` (importing `@whytide/ai`, never `@mastra/*`), Next.js in `ui/`, every screen string a key in `messages/en.json`, the registries in `permissions.ts`, `prices.ts`, `events.ts` and `settings.ts`, the tests in `tests/`.
3. Commands, from the repository root: `pnpm -F discovery build`, `pnpm -F discovery typecheck`, `pnpm -F discovery test`, `pnpm -F discovery lint`. After a change to `workflows/workflows.ts`, `pnpm -F worker test:replay` must still replay `workflows/__histories__/discovery_import_run.json`; a change it cannot replay records a new one with `pnpm -F worker history:record` (core/apps/worker/README.md).
4. Stay inside this folder and the module's schema file. A change to a shared package is its own task.
5. The upload runs outside the request's tenant run (`whytide:own-runs`), and the run's activities in the worker have no request. Their database steps go through `inRun(tenant, …)` in `domain/store.ts`; nothing calls `tenantClient` or `currentTenant()` outside one. `workflows/workflows.ts` runs in Temporal's sandbox: it imports `@temporalio/workflow` and types only, and its inputs and results carry ids, codes and counts, never a cell.
