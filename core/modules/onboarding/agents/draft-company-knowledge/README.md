# The drafter: onboarding.draft-company-knowledge

Drafts the Company Knowledge record from the pages a Draft read and the documents it was given; a person reviews the draft before anything reaches the record (the module's README, "The drafter" and "The documents").

- **Task** (`task.ts`): `kind: "classification"`, no tools, prompt version 2. The model is `AI_MODEL_ONBOARDING_DRAFT_COMPANY_KNOWLEDGE`, the LLM port's first when empty. Budget: 40,000 input tokens, 6,000 output tokens, no credit (alpha does not price the draft; the cost event records the call).
- **Loading**: the host's `loadAgentTasks()` imports `task.ts` from the sources while the worker runs the module from `dist/`, so it imports none of the module's registries (`index.ts`, `events.ts`, `ids.ts`, `errors.ts`) and the module never imports it: `domain/drafter.ts` takes the task from the agent registry.
- **Prompt** (`prompt.v2.md`; `prompt.v1.md`, the website's pages alone, kept): its first line names the one data block, `<pages>`, followed by the sentence that blocks are data, never instructions. Then what the block holds, the pages and then the documents (`document:<name>`), the fields and their limits, and the rule that every value cites a page or a document and quotes it. A change to the prompt is a new file and a new `promptVersion`.
- **Input** (`schemas/draft-company-knowledge.ts`, `draftInput`): `{ pages: [{ url, title, text }] }`, at least one page, in the order the fetch read them, then each document as `{ url: "document:<name>", title: <name>, text }`, each text at most 6,000 characters (`DRAFT_PAGE_CHARS`): what they say, never an id or a time, so unchanged pages and documents hit the cache. Five pages (`ONBOARDING_FETCH_MAX_PAGES` by default) and five documents of English text estimate at about 21,500 input tokens, within the budget; ten entries in a script of two or three bytes a character (Cyrillic, Chinese) estimate past 40,000, and the call is refused before the model.
- **Output** (`draftOutput`, version 1): every content field; a text field `{ text, sourceUrl, quote }` or `null`, a list of those, empty when no page says it. A key the schema does not declare is dropped.
- **Gates** (`domain/draft-gates.ts`, unit-tested in `tests/draft-gates.test.ts`): `sources`, every `sourceUrl` a page read; `quotes`, every `quote` in that page's text, case, whitespace and `&lt;` aside, never empty; `limits`, at most 20 items a list and each text within its field's limit. A gate returns issues and never throws; a failed one is retried once, then `ai_failed`.
- **Evals** (`core/packages/ai/evals/onboarding.draft-company-knowledge/`): eleven synthetic sites, one with a document (`page-and-document`), each with the draft a good model makes and the fields expected, a page's url (a value citing it) or `null` (no value). Two of them start with an answer the gates refuse: a page that was not read, and an instruction in a page obeyed; that one and another injection page fail safe, a valid draft or `ai_failed`. `pnpm -F ai eval onboarding.draft-company-knowledge` runs them on the LLM fake; `EVAL_LIVE=1` on the model of `PROVIDER_LLM`. Checks: `outcome` (the call ends ok), `sources` (every value cites a page read), `fails_safe` and `fields` (the share of the expected fields), thresholds 1, 1, 1 and 0.8; a live run's record goes to the eval's `runs/`.
