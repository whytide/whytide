# onboarding: runbook

- **Settings**: `ONBOARDING_FETCH_MAX_PAGES` (1 to 10, 5 by default), the pages a Draft reads, home page included, read at the worker's start; `AI_MODEL_ONBOARDING_DRAFT_COMPANY_KNOWLEDGE`, the drafter's model as the LLM port names it, the port's first when empty; `ONBOARDING_MAX_FILES` (5) and `ONBOARDING_MAX_FILE_BYTES` (10 MB), the documents a Draft takes and one file's bytes, each 1 or more with no maximum, read at the api's and the worker's start (README "Settings": a changed value needs both restarted; more files can meet the Draft's 10 MB body, 413 `payload_too_large`, after 69 full three-byte documents, but the drafter's budget comes first, long before it).
- **Failure modes**: 400 `validation_failed`: `details.fields` names the text or list off its limits by its path. 400 `company_knowledge_invalid_url`: `details.fields` names the website or proof point page that is not an absolute `http` or `https` address, or carries a user name or password. 400 `documents_too_many`: a Draft of more documents than `ONBOARDING_MAX_FILES`, `details.files` the setting; 413 `payload_too_large`: a Draft whose texts pass its 10 MB body (README "Settings"; every other route takes 1 MB). 500 `tenant_mismatch` from `readCompanyKnowledge`: the caller passed another workspace than its run's. 409 `company_knowledge_no_website`: a Draft before a website was saved. A run's `fetchError`: `egress_blocked_address` (a private or reserved address, also every name behind a proxy in fake-IP mode, `198.18.0.0/15`), `egress_dns_failed`, `egress_timeout`, `egress_too_large`, `egress_too_many_redirects`, `egress_insecure_redirect`, `egress_request_failed` (connection or TLS), or `fetch_failed` (no HTML page, `robots.txt` disallows the home page, or the activity's attempts spent); the drafter's `ai_failed` (the answer failed its schema or a gate twice: the decision record's `gates` names each issue) or `draft_failed` (its attempts spent: the model's port, the database, or 500 `draft_agent_not_loaded` in the worker's log, the task not registered at its start). 409 `company_knowledge_no_draft`: an accept or a discard with no pending draft, often one already accepted. The screen's own failures show the code in words with a retry; the api's log has the request.
- **A prompt change**: a new `prompt.v<N>.md` and `promptVersion`, then `pnpm -F ai eval onboarding.draft-company-knowledge`, on the fake and, by hand, live (`EVAL_LIVE=1`; commit its record from the eval's `runs/` with the change).
- **Events**: `onboarding.company_knowledge_updated` and `onboarding.draft_requested` rows in `outbox`, delivered by the worker; a dead one is replayed with the platform's `replayDeadLetter`.
- **The script** (`pnpm knowledge:draft`, README "The script"): its printed code says how it ended (through pnpm, any exit code but 0 is 1): 0 done, 1 refused before any write (a document's code and path, or the record's code), 2 usage, 3 the run failed (its code, as above), 4 superseded, 6 `workspace_not_found` (an id or a slug of no workspace), 5 the wait of twenty minutes ran out: the worker goes on and the draft shows in the Company screen; "is the worker running?" while the run is still `fetching`, then check as for a stuck run.
- **A stuck run**: a record left `fetching` or `fetched` for more than twenty minutes by its `updated_at` (no worker, the event not yet delivered, or a run that died) reads "it may be stuck" on the screen, which stops asking for it. Check the `onboarding.draft_requested` row in `outbox` (delivered, or dead) and the worker's log for the workflow `onboarding.draft:<workspaceId>:<draftRunId>`; then press Draft from website, which starts a new run and supersedes the old one, whose writes compare `draft_run_id` and so write nothing.
