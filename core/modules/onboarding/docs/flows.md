# onboarding: flows

- **Reading** (`GET …/onboarding/company-knowledge`): the api host's guards, then the handler in the request's tenant run. The first read of a workspace inserts its record with `ON CONFLICT DO NOTHING`: a second first read at the same time waits for the first one's commit, skips its insert and answers the same row.
- **Saving** (`PUT …/onboarding/company-knowledge`): the body's schema checks the lengths and counts (400 `validation_failed`); `saveCompanyKnowledge` trims the texts, drops repeated items, checks the URLs (400 `company_knowledge_invalid_url`, nothing written), locks the record's row, compares each content field with what is stored and writes; on a change it marks the changed fields `human`, moves the version and writes `onboarding.company_knowledge_updated` `{ workspaceId, version }` to the outbox in the same transaction, which the worker delivers.
- **Drafting from the website** (`POST …/onboarding/company-knowledge/draft`, README "The website fetch"): the idempotency check, then `requestDraft` in the request's tenant run: the record's row locked, 409 `company_knowledge_no_website` without a website, a new `draftRunId`, `fetching`, and `onboarding.draft_requested` in the outbox, all in one transaction, the pending draft cleared; 202 with the record. The worker delivers the event in its workspace's tenant run; the subscriber starts `onboarding_draft_company_knowledge` for that workspace by `onboarding.draft:<workspaceId>:<draftRunId>`. Its activity reads the website in a tenant run, closes it, fetches `robots.txt`, the home page and the chosen links through `fetchSafe`, then writes in one tenant run: the row locked, the run compared with `draftRunId`, the pages replaced and the status set, or nothing when a later Draft started. The screen asks for the record every two seconds while it is `fetching` or `fetched`, until the run ends, a read fails (its retry resumes the asking) or the run is stuck, ten minutes by `updatedAt`.
- **Drafting with the script** (`pnpm knowledge:draft`, README "The script"): the files read and checked in the script's process, nothing written on a refusal; then one tenant run: the website saved with `--url`, `requestDraft` with the documents, which replaces the record's in the run's transaction; the worker's run as above. The script reads the record every two seconds, each read its own tenant run, until the run ends, a later Draft supersedes it or ten minutes pass; with `--accept`, one tenant run locks the row, checks that the run is still the latest and accepts as the route does.
- **Drafting from the pages** (README "The drafter"): when the fetch ended `fetched`, `onboarding_draft_from_pages` reads the pages, then the Draft's documents, in a tenant run and closes it; `callAgent` asks the model outside any run, opening its own for the cache, the decision record and the cost event; a last tenant run locks the row, compares the run and writes `pendingDraft` and `drafted`, or `failed` with `ai_failed`, or nothing when a later Draft started. Past its attempts, `onboarding_draft_failed` writes `failed`, `draft_failed`, the same way.
- **Reviewing the draft** (`POST …/draft/accept`, `…/draft/discard`): the idempotency check, then in the request's tenant run the row locked, 409 `company_knowledge_no_draft` without a draft; an accept writes the drafted fields the rule lets through, marks them `ai_draft`, moves the version and writes `onboarding.company_knowledge_updated` to the outbox, the draft cleared, in one transaction; a discard clears the draft.
- **The screen** (`/w/{ws}/company`): the page renders the title; the screen reads the record through the web's browser client, to the api through the web's `/api` proxy, with its loading and error states; Save sends the whole form the same way and shows what it answered. A Draft while a draft waits for review asks first, since the Draft drops it. A failed write's retry sends the same `Idempotency-Key`, so that the api runs it once.
- **Writing** (alpha-p7): the writer calls `readCompanyKnowledge(workspaceId)`, the own-employee filter `getCompanyDomain()`, inside their own tenant run.
