# onboarding: security

Read before changing the module ([security §8](../../../../docs/rules/security.md#8-conduct)).

- **Tenancy**: every query goes through the caller's tenant run (`tenantClient`), scoped to its workspace, which comes from the URL, never from a body; the Draft's subscriber starts the workflow for the workspace of the event's tenant run (`currentTenant()`), never the payload's; `readCompanyKnowledge` refuses another workspace than its run's (`tenant_mismatch`). `tests/tenancy.test.ts` registers `company_knowledge`, `website_pages` and `company_documents` in the two-workspace harness and checks the public reads and the pages' read with `assertScoped`.
- **Who may do what**: `company_knowledge.read` (Owner, Admin, Member) on `GET`, `company_knowledge.write` (Owner, Admin) on `PUT`, the Draft, the accept and the discard, the last three `@Idempotent()`; the roles are kept, not evaluated, in alpha.
- **URLs**: the website and a proof point's page are absolute `http` or `https` addresses without a user name or password; a proof point may also cite a document, `document:<name>`, a name with no control character or slash. The screen links only a page that starts with `http://` or `https://`, in a new tab with `rel="noopener noreferrer"`: no referrer, no handle on this page; a document shows as its name, as text.
- **The documents** (README "The documents"): an engineer's files, parsed in the script's own process, or a member's, parsed in their browser by the Company screen, never in the api, which never loads PDF.js (it adds globals on its first call); the worker loads it only through the platform's site reader (`readPage`), by a dynamic import at the first PDF, where the globals it adds (`DOMMatrix`, `pdfjsWorker`, `pdfjsLib`, `_pdfjsTestingUtils`, `Math.sumPrecise`) touch neither `fetch`, sockets nor the egress client (platform README, "The site reader"); onboarding's own documents are never parsed in the worker: at most `ONBOARDING_MAX_FILES`, `.pdf`, `.txt` or `.md` only, `ONBOARDING_MAX_FILE_BYTES` each (five and 10 MB unset, README "Settings"), checked before a byte is parsed. The screen loads PDF.js (unpdf's build, on the page's thread) only once a PDF is picked, with the same options, and sends the api the texts only, never a file; the api checks them again (`draftBody`: a name with no control or format character, a slash or a backslash, 50,000 characters without U+0000; `requestDraft`: `ONBOARDING_MAX_FILES` at most), names a refusal's field and never its value, and takes no more than a 10 MB JSON body on the Draft (`DRAFT_BODY_BYTES`, the route's own limit; every other route keeps the api's 1 MB). PDF.js (through `unpdf`) gets the bytes as `data`, never a URL, with `useWorkerFetch: false`, `useWasm: false` and `verbosity: 0`: it fetches nothing (`tests/documents.test.ts` refuses every fetch and socket while it parses and sees none) and prints nothing; it runs no eval in 6.4. An encrypted or damaged PDF stops the script with its code. The text is cut at 50,000 characters; no line the script prints carries a document's text. A document is untrusted like a page: it reaches the model only in the `<pages>` block, and the gates hold a document's quote to its text.
- **The fetch** ([security §5](../../../../docs/rules/security.md#5-requests-uploads-and-egress)): only in the worker's activity, never in a request, and only through the platform's `fetchSafe`, which refuses private, link-local and metadata addresses on every hop; the activity takes ids only and never an allow- or deny-list. Its bounds: one megabyte, ten seconds and five redirects a page, 500 KiB of `robots.txt`, sixty seconds in all, `ONBOARDING_FETCH_MAX_PAGES` (at most 10) pages, same host only, HTML only, a compressed body never inflated; the text is cut at 50,000 characters, the title at 500, the links counted at 500 a page. The parser is one pass over the page, linear in its length. `robots.txt` is honoured. A blocked address and a name that does not resolve read the same on the screen, so that nobody learns which names resolve to private addresses.
- **The drafter** ([security §6](../../../../docs/rules/security.md#6-ai), README "The drafter"): the pages are untrusted; they reach the model only in the `<pages>` data block, every `<` written `&lt;` so that a page cannot close it, after the system prompt's sentence that blocks are data, never instructions. The task has no tools. Its answer is parsed against the output schema, which drops any key it does not declare, then the gates in code: every value cites a page read and quotes words of that page, within the record's limits; a failure is retried once with the issues (paths and rules, never a page's words), then `ai_failed`, with nothing written. A draft reaches the record only when a person accepts it, a field a person wrote only with "replace my edits". The run's writes compare `draftRunId` under the row lock, so a superseded run writes nothing.
- **What the AI sees**: the pages and the documents (above), and the record in the writer's prompt (alpha-p7) as data in delimited blocks; its limits keep them bounded: 2,000 characters for the long description, 20 items per list; the drafter reads every page and document whole, 50,000 characters each at most, ten pages and `ONBOARDING_MAX_FILES` documents at most (five unset), within its budget of 800,000 input tokens, which more documents can pass (README "Settings").
- **Personal data**: not by design, but present (docs/data.md). The fetch reads the company's public pages, its about, team and customer pages among them, and the script and the Company screen read the documents a person gives them (a deck may name customers and staff), so people's names and words (team members, customers quoted in testimonials) can be in the stored pages and documents, in the drafter's prompt sent through the LLM port, in the decision record's raw prompt, kept `AI_RAW_RETENTION_DAYS` (30 by default), and in `pending_draft`, then in the record once a person accepts it. The events carry ids and a version; an error's details carry paths, never a value. No log line, failure or Temporal history carries a page's text, title or address, nor a document's text: the activity returns a status, a count and a code, and the script prints names and codes. Page text reaches the screen as text, and the drafter as data, never instructions; the decision record keeps the raw prompt until `AI_RAW_RETENTION_DAYS`.
