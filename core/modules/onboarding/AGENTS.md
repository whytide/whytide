# onboarding: the brief for a coding agent

1. Read `README.md`, then `docs/concepts.md`, `docs/data.md`, `docs/flows.md`, `docs/security.md` and `docs/runbook.md`. They say what is true now and change in the same merge request as the behavior.
2. The rules: [coding](../../../docs/rules/coding.md), [security](../../../docs/rules/security.md), [delivery](../../../docs/rules/delivery.md). The shape of this folder is [architecture §4.2](../../../docs/architecture.md#42-inside-a-module): the fields and rules in `domain/` without a framework, the workflow and its activities in `workflows/` (a change to the workflow's code records a new history), the Zod schemas in `schemas/`, the routes in `api/`, the screen in `ui/` (compiled and type-checked by the web host), every screen string and error code a key in `messages/en.json`, the registries in `permissions.ts`, `events.ts`, `errors.ts` and `ids.ts`, the tests in `tests/`.
3. Commands, from the repository root: `pnpm -F @whytide/onboarding build`, `typecheck`, `test`, `test:tenancy`, `lint`; `pnpm -F api test` for the routes (`core/apps/api/tests/onboarding-company-knowledge.test.ts`); `pnpm -F worker test` and `pnpm -F worker test:replay` for the workflow (`core/apps/worker/tests/onboarding-fetch.test.ts`, `workflows/__histories__/`); `pnpm -F web typecheck` and `pnpm -F web test` for the screen (`core/apps/web/tests/company-screen.spec.ts`, `onboarding-draft-button.spec.ts`, `draft-review.spec.ts`, `onboarding-states.spec.ts`); `pnpm -F platform messages:check` for its keys; `api-calls/alpha-p10-090-onboarding.http` holds a request per route.
4. Every query goes through `tenantClient`, inside the caller's tenant run; no command opens a run or keeps a client. A new content field changes `domain/fields.ts`, the schema, `onboarding.prisma` with a migration, the form and `messages/en.json` together.
5. Tests import `domain/`, never `index.ts`, `api/` or a host. Stay inside this folder and `onboarding.prisma`; a change to a shared package is its own task.
