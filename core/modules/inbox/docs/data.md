# inbox: data

Five tenant tables in `packages/db/prisma/schema/inbox.prisma`, migrations `20261029145816_inbox_initial`, `20261029173053_inbox_reply_labels` (beta-p5-040), `20261102131049_inbox_replies` (gamma-p4-060), `20261103213915_inbox_reply_drafts` (inbox-reply-draft), `20261112151322_inbox_reply_classifications` (gamma-p4-040) and `20261112230729_inbox_reply_label_classes` (gamma-p4-055):

- `threads` (`thr_`): `workspace_id`, `channel` (`linkedin`), `sender_account_id` (linkedin's), `owner_user_id` (the account's owner at the first message), `person_id` (contacts'), `provider_thread_ref`, `last_message_at` (moved forward only), `created_at`, `updated_at`. Unique `(workspace_id, channel, provider_thread_ref)`; indexes `(workspace_id, last_message_at)` and `(workspace_id, person_id)`.
- `messages` (`msg_`): `workspace_id`, `thread_id` (a foreign key to `threads` by `(workspace_id, thread_id)`, restrict), `person_id`, `direction` (`in`, `out`), `sent_by` (`campaign`, `user`; null exactly when `direction` is `in`, the CHECK `messages_sent_by`), `step_execution_id` (campaigns', beta-p5-020), `body`, `provider_message_ref`, `sent_at` (the provider's), `received_at` (the store's), `approved_by`, `approved_at` (a campaign message's, from approvals), `opt_out_matched`, `owner_notified_at` (beta-p5-030); a reply from the inbox's (gamma-p4-060) `send_status` (enum `message_send_status`: `sending`, `sent`, `refused`, `failed`), `error_code` (linkedin's or inbox's code of a refused or failed one) and `created_by` (identity's user id of the member who pressed Send). The hand-written CHECK `messages_send_status`: the three null, or a status on an `out`, `sent_by = user` row with its member, a code only when `refused` or `failed`. A reply's `sent_at` is the press until it is sent, then the provider's; its `provider_message_ref` null until then. Unique `(workspace_id, provider_message_ref)` and `(workspace_id, step_execution_id)`; index `(workspace_id, thread_id, sent_at)`.
- `reply_labels` (`rlb_`, beta-p5-040): `workspace_id`, `message_id` (a foreign key to `messages` by `(workspace_id, message_id)`, `ON DELETE CASCADE`), `label` (enum `reply_label`: `positive`, `not_positive`), `class_label` (gamma-p4-055: text, the thread owner's label among campaigns' 7; null on beta's rows), `labeled_by` (identity's user id of the member who chose it, the thread's owner since gamma-p4-055), `labeled_at`. The hand-written CHECK `reply_labels_class_label`: `class_label` null, or one of the 7 with `label` following it, `positive` exactly for `interested`. Unique `(workspace_id, message_id)`: one label per reply, changed in place. Only an inbound message gets one (the label refuses another, `message_not_inbound`). `messages` gained the unique `(workspace_id, id)` the key points at.
- `reply_drafts` (`rdr_`, inbox-reply-draft): `workspace_id`, `thread_id` (a foreign key to `threads` by `(workspace_id, thread_id)`, `ON DELETE CASCADE`), `requested_by` (identity's user id of the member who asked), `status` (enum `reply_draft_status`: `drafting`, `ready`, `failed`), `brief` (the member's, trimmed, null for none), `text` (the writer's answer), `replaced_text` (the ready text this draft replaced, for the writer's `<replaced>`), `error_code` (a failed one's: messaging's writer's, a provider's, `write_failed` or `draft_stuck`), `model_id`, `prompt_version` and `decision_record_id` (ai's record of the last call), `requested_at`, `updated_at`. The hand-written CHECK `reply_drafts_status`: a text exactly when `ready`, a code exactly when `failed`. Unique `(workspace_id, thread_id)`: one draft per thread, replaced by a new row at each request; unique `(workspace_id, id)`; index `(workspace_id, status, requested_at)` for the sweep.
- `reply_classifications` (`rcl_`, gamma-p4-040; README "The classifier"): `workspace_id`, `message_id` (a foreign key to `messages` by `(workspace_id, message_id)`, `ON DELETE CASCADE`), `thread_id`, `person_id`, `label` (text, the 7 labels gamma writes and the 15 of RB-13.2.1, 20 values), `confidence` (0 to 1), `is_suggested`, `opt_out_detected`, `entities` (JSON, `{ returnDate }` only), `origin` (`phrase`, `model` or `fallback`), `decision_record_id`, `model_id` and `prompt_version` (ai's record of the call, required for `model`), `actions_taken` (JSON, campaigns' answer `{ actions, enrollmentIds }`), `created_at`. The hand-written CHECK `reply_classifications_values` holds the label, the confidence, the origin and a model's call. Unique `(workspace_id, message_id)`: one per reply, written once; index `(workspace_id, person_id, created_at)`.
- No foreign key leaves the module: the other ids are plain.
- PII: `messages.body`, the person's words as the provider gave them, or the member's reply; `reply_drafts.brief`, `text` and `replaced_text`, the member's brief and the AI's drafts, which may hold the person's name. No other column holds a text or a name; a label is a word and ids. A reply's request file, `raw/inbox/<messageId>/send.json`, holds its text and the person's member id until the send settles (then deleted), 72 hours at most.
- Retention: until the person is erased: `erasePerson` deletes the person's messages and every message of their threads, then their threads (privacy's deletion script); a message's label and classification go with it, and a thread's reply draft with its thread, by the cascades. A reply that comes after the erasure stores nothing: the store asks contacts first. The message's file under raw/ is deleted by the store, else expires after 72 hours.
- Grants: the owner's default privileges give `app` select, insert, update and delete, as alpha's tenant tables; no row-level policy before zeta.

## The reply golden set's line

`exports/reply-labels-<UTC date>.jsonl`, or `exports/reply-labels-<ISO week>.jsonl` (beta-p7-030; [README](../README.md#the-reply-golden-set)): one JSON object a line, per labeled reply, in the order the labels were chosen.

| Key | |
|---|---|
| `person_sha256`, `thread_sha256` | the sha256, in hex, of the person's id and of the thread's id; no id of the person, the thread, the message or the member |
| `channel` | the thread's channel, `linkedin` (or `email`, once the email phase gives a thread that channel; gamma-p7-060) |
| `label`, `labeled_at` | the reply's latest label (`reply_labels.label`), `positive` or `not_positive`, beta's word, which follows the thread owner's class since gamma-p4-055 (`positive` for `interested`), and when it was chosen |
| `class_label` | the thread owner's class among the 7 (`reply_labels.class_label`, gamma-p4-055), or null on beta's rows (gamma-p7-060) |
| `received_at`, `text` | the reply: when Whytide stored it (`messages.received_at`), and its text |
| `opt_out_matched` | whether the store's phrases matched the reply (`messages.opt_out_matched`; gamma-p7-060) |
| `classification` | the reply's classification (`reply_classifications`, one per reply), whatever its origin, `{ label, confidence, is_suggested, origin, prompt_version }`, or null until classified (gamma-p7-060) |
| `earlier` | the thread's messages sent before the reply, by `sent_at` then id, the latest 10 (`EXPORT_EARLIER_MAX`), oldest first, each `{ direction, sent_by, text, at }`: `in` or `out`; `campaign`, `user`, or null for the person's; the text; its `sent_at` |

In every text, the person's first and last names (contacts' `getLead`) are `[first_name]` and `[last_name]`: whole words, any case, in any script. Another name a text holds, a colleague's or the sender's, stays as written.
