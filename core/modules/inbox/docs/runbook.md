# inbox: runbook

No setting. Logs: the worker's lines for the activities `inbox_store` and `inbox_mail_reply`, ids only; this module logs two lines itself, `inbox: no reply mail, the owner is unavailable`, with ids, and `inbox_sent_message_unmatched` (below).

- **A reply not stored:** find `linkedin.message_received` in `outbox` by `payload.person_id`. None: the receiver dropped or never got it (linkedin's runbook, `linkedin_event_receipts`). Not delivered: the worker's outbox. Delivered: the workflow `inbox.message:<workspaceId>:<event id>` in Temporal, whose activity's last failure names the code.
- **`inbox_file_invalid`:** the file did not parse, or its direction is not the event's. An inbound message's steps are held; the file stays under `raw/linkedin/messages/` for 72 hours. Read it through the files port, never into a log.
- **A missing file:** the steps are held and nothing is stored: the worker was down past raw/'s 72 hours. The message is lost to the inbox; the gate's `last_inbound_at` stays.
- **A failed run** (`sender_account_not_found`, the database): the run rolls back with its hold, and Temporal tries it again; the receiver's `last_inbound_at` keeps the gate blocking the person's next step meanwhile.
- **A wrong opt-out:** an opt-out is never removed (contacts).
- **`inbox_sent_message_unmatched`** (beta-p5-020): a sent message step whose `campaigns.step_sent` found no `succeeded` step, no approved text (approvals' `approvedContent`) or no refs (linkedin's `sentMessageRef`, the outreach row's last send), or whose ref another step's row holds. The line names the step's id: read the step, its approval item and the person's `sender_outreach` row. Its message stays out of the thread; the echo, if it came, stays the user's.
- **A reply mail not received** (beta-p5-030): find the reply's message, its `owner_notified_at`. Set: the mail went; in development it is in Mailpit (the shared stack's inbox), else the owner's mail server has it. Unset: the workflow `inbox.reply_mail:<workspaceId>:<messageId>` in Temporal. None: `inbox.reply_received` was not delivered (the worker's outbox). Ended: its answer's `reason`, `owner_unavailable` for an owner who is no user or is disabled (the worker's `info` line names the ids), `gone` for a reply erased since. Failed: the activity's last failure names the code, the port's `mail_unreachable` or `mail_rejected` (the SMTP settings, `PROVIDER_APP_MAIL`) after five attempts. A mail without a link: `APP_PUBLIC_ORIGIN` is empty in the worker's environment.
- **The reply golden set** (README "The reply golden set"): `pnpm inbox:export-labels [--workspace <id or slug>] [--week 2026-W44]` on a laptop; on the production machine, from `deploy/`, `docker compose exec -e LOG_LEVEL=warn api node ../../modules/inbox/dist/cli/export-labels.js [options]` (`LOG_LEVEL=warn` hides the platform's JSON log lines). The last line, `reply_labels_total`, gives beta's two numbers: the replies labeled, and the testers with a positive reply. `files_too_large`: a workspace's set passed 25 MiB, export it by week. `week_invalid`: a week its year does not have, or one not started. A file stays 7 days under `exports/`; read it before it leaves the machine.
