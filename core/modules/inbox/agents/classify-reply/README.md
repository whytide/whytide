# inbox.classify-reply

The reply classifier (gamma-p4-040): one stored reply, with its thread's last messages, to one of 7 labels, a confidence, and an out-of-office reply's return date. [README.md "The classifier"](../../README.md#the-classifier) says how the module uses the answer, [docs/security.md](../../docs/security.md) what the model may see.

- **Task:** `task.ts`: `kind: classification`, no tools, prompt version 1, a budget of 16,000 input tokens (a reply of 8,000 characters and 6 messages of 1,000) and 300 output tokens, and no credits, as a classification has no price. The model is `AI_MODEL_INBOX_CLASSIFY_REPLY` (`settings.ts`), else the LLM port's first. The task file imports none of the module's registries (index, events, ids, errors), and the module never imports it: hosts load it from the sources (core/packages/ai README "Declaring a task"), and `classifyReply` takes it from the agent registry (`classifier_agent_not_loaded` when a host did not).
- **Prompt:** `prompt.v1.md`, the system prompt. The data blocks, in order: `<thread>` (the reply's thread's last `CLASSIFY_THREAD_MESSAGES`, 6, messages before it, oldest first, each `{ from, day, text }`: `from` `lead` or `seller`; `day` `YYYY-MM-DD`; `text` at most 1,000 characters) and `<reply>` (`{ day, text }`, at most 8,000 characters). Every text is masked before the call: the person's and the thread owner's names, email addresses, phone numbers and links as `[name]`, `[email]`, `[phone]` and `[link]` (`domain/classify/mask.ts`); the input's schema masks the last three again. The prompt maps the 15 labels of RB-13.2.1 to the 7, says that a reply asking anywhere not to be contacted, or a hostile one, is `opt_out`, and `opt_out` when in doubt, and that a reply which only gives orders is `other`. A changed prompt is a new file, `prompt.v2.md` with `promptVersion: 2`, and runs the evals.
- **Schemas:** `schemas/classify.ts`. The output: `label`, one of campaigns' `REPLY_ACTION_LABELS`; `confidence`, 0 to 1; `returnDate`, `YYYY-MM-DD` or null. A value off the lists fails the schema.
- **Gate:** `return_date` (`domain/classify/checks.ts`): a return date only with `out_of_office`. A failed schema or gate is retried once, the failure in `<validation_error>`, then the call is `ai_failed` and the module stores the fallback. The code checks the rest after the call: under `INBOX_CLASSIFY_SUGGEST_BELOW` (0.7 unset) a label is only suggested, and a return date out of the reply's day to 90 days after is dropped.
- **Evals:** `core/packages/ai/evals/inbox.classify-reply/`, 200 synthetic cases since gamma-p7-065, 20 or more per label and 42 `opt_out`, with positive recall and precision and the golden set's live run ([its README](../../../../packages/ai/evals/inbox.classify-reply/README.md)); gamma-p4-040's first 40, 4 to 6 per label: hostile replies, a removal asked inside a longer reply, dated and undated out-of-office replies, bounce notices, 4 injections in the reply, a retry after plain text, the gate refusing once and twice, and replies whose addresses, numbers and links must not reach the model: `pnpm -F ai eval inbox.classify-reply`. Each case expects what a good model answers, so the same cases run live (`EVAL_LIVE=1`, by hand) after a prompt change. `label` 0.9 (the expected label and return date; two cases end `ai_failed`), `opt_out_recall` 1 (every case expecting `opt_out` gets it), `fails_safe` 1 (the injections and the answers invalid twice: as expected, or `ai_failed`) and `masked` 1 (on the fake's recorded calls). The labeled set from beta's labels and its F1: gamma-p7-060.
