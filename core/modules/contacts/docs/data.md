# contacts: data

Ten tenant tables in `core/packages/db/prisma/schema/contacts.prisma`, created by the migrations `20261022150500_contacts_initial`, `20261022180000_contacts_leads`, `20261022210000_contacts_review_decisions`, `20261029091739_contacts_suppression` and `20261029101240_contacts_outreach_status`; `20261102113200_contacts_lead_audience` adds `leads.icp_id_scored` and its index (gamma-p5-055), `20261102125800_contacts_suppression_channels` the suppression channels and the relationship layer (gamma-p2-040), and `20261103185440_contacts_lead_source_manual` the source kind `manual` (lead-manual-create); `20261104101137_contacts_title_hashes_reset`, data only, deletes once the `rejected_candidate` hashes whose only reason is `title_mismatch` (title-check-ai); `20261112231349_contacts_exclusion_lists` adds `exclusion_lists`, `suppression_entries.exclusion_list_id` and the source `csv` (gamma-p2-045); `20261113030128_contacts_exclusion_list_domains` adds a ninth, `exclusion_list_domains`, and fills it from the lists' `csv` entries (review-gaps); `20261113114002_contacts_enrichment` adds `leads.enrichment_hold_until` and its partial index, and `workspace_companies.employee_count` and `description` with their CHECKs (gamma-en-040); `20261114134946_contacts_shared_companies` adds `workspace_companies.company_id` and two global tables, `companies` and `group_companies` (gamma-rf-010, below); `20261114165214_contacts_suppression_email` adds the match type `email`, `suppression_entries.email` and a tenth table, `person_email_hashes` (gamma-rf-040, below); `20261115045222_contacts_person_without_linkedin` drops `NOT NULL` from `persons.linkedin_url`, for a person known by an email address alone (gamma-rf-050), expand only. Every id is `<prefix>_<ULID>` (`ids.ts`), every row has its `workspace_id`, every time is a `timestamptz`.

**PII classes** (`domain/fields.ts`; a `/// pii: <class>` line above each such column; data model §2.6): `business_contact` for the `persons` columns about the person (`linkedin_url`, `provider_refs`, `first_name`, `last_name`, `headline`, `title`, `company_name`, `location_text`, `location_country`); `personal` for `person_hashes.hash`, `suppression_entries.hash` and `person_email_hashes.hash`, pseudonymous, and for `suppression_entries.email`, the address a member blocked, which the list shows and erasure empties (gamma-rf-040); `business_contact` for `leads.why`, whose bullets may quote the profile, for `review_decisions.reason_text` and `good_reason_text`, the tester's words, and for `suppression_entries.linkedin_url`; `none` for the rest, every `workspace_companies`, `companies`, `group_companies` and `lead_status_changes` column, every other `leads` column, `persons.last_touch_at`, `suppression_entries.domain` (as `workspace_companies.domain`), `suppression_entries.relationship`, `suppression_entries.exclusion_list_id`, every other `person_email_hashes` column, every `exclusion_lists` column and every `exclusion_list_domains` column, its `hash` a company domain's (no person id, so no eraser), included: a lead copies no field of its person. `tests/schema.test.ts` holds the tables to this list.

**Provenance**: `field_provenance` is `{ <field>: { source, provider, at } }`, one entry per field with a value or that a member cleared, keyed by the camelCase name, `source` one of `linkedin`, `import`, `website`, enrichment's `open_data`, `data_vendor`, `web_search` and `ai_inferred` (gamma-en-040), and `member` (a member's own value, lead-fields-edit), `provider` an adapter's or a source's name as providers' `ADAPTER_NAME` takes it (`unipile`, `csv`, `wikidata`, …), or null; `provider_refs` is `{ <provider>: <member id> }`.

**Retention**: a person, its lead, its review decisions and its status changes until `erasePerson` (or, later, the workspace's deletion); a `rejected_candidate` hash 90 days, then `purgeExpiredHashes`; an `erased` hash for good; an address's hash until its person's erasure (gamma-rf-040); a suppression entry for good, a removed one with its removal; an exclusion list the same way, the file itself never; a shared company and a group's row for good, as no command deletes one (gamma-rf-010).

**Suppression entries** (beta-p2-010): `hash` is `hashOf` of the normalized value, `url:` of a profile (`https://linkedin.com/in/<slug>`) or a company page (`https://linkedin.com/company/<slug>`), `domain:` of a domain (lowercased, without a scheme, `www.`, a port or a path), `email:` of an email address (trimmed and lowercased, nothing else folded; gamma-rf-040); `linkedin_url`, `domain` or `email` keeps the value itself, for the list to show. The match reads `hash` only. `erasePerson` sets `linkedin_url` to null on every entry holding the person's profile hash, in both layers, and keeps the row and its hash, so that the person imported again is still suppressed; it sets `email` to null on every entry holding one of the person's address hashes, which it deletes from `person_email_hashes`; a company's entry stays as it is. A person without a LinkedIn profile has their entries on their address hashes, with `email` null from the start (gamma-rf-050). No row is ever deleted (gamma-p2-040): the migration `20261102125800_contacts_suppression_channels` revokes DELETE on the table from `app`, and the api's e2e reset deletes with the owner's client. Its CHECK on the new layer compares `layer::text`, since Postgres refuses an enum value in the transaction that adds it.

**Outreach status** (beta-p2-030): `recordLeadStatus` locks the lead's row (`FOR UPDATE`), writes `outreach_status` and `outreach_reason` with a raw `UPDATE`, so that `updated_at`, the list's time of qualification, stays, and inserts one `lead_status_changes` row. `erasePerson` deletes the person's changes before the lead, the one path that deletes one; its counts leave them out.

**Sorts** (`domain/leads.ts`): `fit` by `fit_score`, none last; `newest` by `created_at`; `unreviewed_first` by `review_status`, none first, then the enum's order (`good_lead`, `not_a_fit`), then as `fit`; each ties by the person id.

**An entry's list** (review-gaps): a `csv` entry belongs to the list that wrote it until that list is removed; then it moves to the earliest created active list whose `exclusion_list_domains` names its hash, taking that list's `relationship`, or, if none does, it is removed. A hand add on an active `csv` entry's key takes it over: `source` `manual`, `exclusion_list_id` null, `created_by` the adder, the rest as stored; no list's removal touches it after.
