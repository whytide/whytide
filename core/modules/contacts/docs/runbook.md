# contacts: runbook

- **Settings**: `HASH_SALT` (README "Settings"). Missing: `hash_salt_missing` (500) at the first upsert, erasure or hash check; set it and restart. Never change it on a running installation: no earlier hash would match, erased people's included.
- **Failure modes**: `person_erased` (409) is expected for an erased person and writes nothing; `linkedin_url_invalid` (400) for a URL off `linkedin.com/in/<slug>`; two runs that create the same new person, or the same person's lead, at once: one fails on the unique key (Prisma P2002) and its caller retries; the batched commands merge such a person instead, and throw after three rounds of it (`other runs kept creating the chunk's persons first`), or when a person they read is erased meanwhile (`a person the chunk read was deleted meanwhile`): the caller's retry runs the chunk again, and the erased hash refuses that person; `contacts_input_invalid` naming `cursor` (400) for a lead cursor that is not the page before's in the same sort; `review_reason_required` and `review_text_required` (400) for a decision without its reason or its words, shown on the panel's field; `contacts_input_invalid` naming `week` for a week the year does not have; `lead_exists` (409, `details.personId`) for Add lead on a person who is a lead already, which the dialog links to; two members who add the same new URL at the same moment: one gets the 500 of the unique key (P2002), and Add again answers `lead_exists` (lead-manual-create).
- **Logs**: no line carries a person's value: the platform's logger redacts the person keys (docs/security.md).
- **Screens**: a read the api fails shows its code in words and Try again, on the list as in a slot of the lead page, whose other slots stay up; a code without a key in the bundle shows nothing.
- **Suppression** (beta-p2-010): `suppression_target_invalid` (400) for a value that names no profile, company page or domain; `suppression_not_removable` (409) for an opt-out, which stays for good; an add that finds the active entry with its key removed in between, three times running, throws (`the active entry with this key kept being removed meanwhile`) and its caller retries. Without `HASH_SALT`, every check throws `hash_salt_missing` (500) rather than answering.
- **Exclusion lists** (gamma-p2-045): a refused file says why in words, and nothing was written: `exclusions_unsupported_type` (not a lone `.csv` part, an .xlsx renamed, a NUL byte or a malformed CSV: export it again as CSV), `exclusions_bad_encoding` (save it as UTF-8), `exclusions_missing_column` (name the column `domain`), `exclusions_too_many_rows` or `exclusions_too_large` (split the file, or raise `EXCLUSIONS_IMPORT_MAX_ROWS` or `EXCLUSIONS_IMPORT_MAX_BYTES` within their bounds and restart the api), `exclusions_no_valid_row` (every row empty, invalid or a duplicate). An import past its 60 s run is rolled back whole: split the file. A list removed by mistake cannot be restored: import the file again, which makes a new list, the removed one kept on record; the leads it had moved are still `suppressed`. A removal waits for an import of the same workspace to end (review-gaps); one that waited past 75 s answers 500 and changed nothing: remove it again. A domain still stopped after its list's removal is held by another active list (its entry now names that list) or by a person's hand add (`source` `manual`).
