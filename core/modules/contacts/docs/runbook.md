# contacts: runbook

- **Settings**: `HASH_SALT` (README "Settings"). Missing: `hash_salt_missing` (500) at the first upsert, erasure or hash check; set it and restart. Never change it on a running installation: no earlier hash would match, erased people's included.
- **Failure modes**: `person_erased` (409) is expected for an erased person and writes nothing; `linkedin_url_invalid` (400) for a URL off `linkedin.com/in/<slug>`; two runs that create the same new person, or the same person's lead, at once: one fails on the unique key (Prisma P2002) and its caller retries; the batched commands merge such a person instead, and throw after three rounds of it (`other runs kept creating the chunk's persons first`), or when a person they read is erased meanwhile (`a person the chunk read was deleted meanwhile`): the caller's retry runs the chunk again, and the erased hash refuses that person; `contacts_input_invalid` naming `cursor` (400) for a lead cursor that is not the page before's in the same sort; `review_reason_required` and `review_text_required` (400) for a decision without its reason or its words, shown on the panel's field; `contacts_input_invalid` naming `week` for a week the year does not have.
- **Logs**: no line carries a person's value: the platform's logger redacts the person keys (docs/security.md).
- **Screens**: a read the api fails shows its code in words and Try again, on the list as in a slot of the lead page, whose other slots stay up; a code without a key in the bundle shows nothing.
