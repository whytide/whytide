# signals.rate-engagement

The rating agent (gamma-p5-030): up to ten of a source's events against the workspace's offer, each its relevance, a one-line rationale and its intent class. [README.md "Rating"](../../README.md#rating) says how a run uses it, [docs/security.md](../../docs/security.md) what the model may see.

- **Task:** `task.ts`: `kind: classification`, no tools, prompt version 1, a budget of 16,000 input tokens (ten long excerpts in a non-Latin script fit) and 2,000 output tokens, and no credits, as the rating has no price. A batch over the budget is refused before the model is asked and stays unrated, as an `ai_failed` one does. The model is `AI_MODEL_SIGNALS_RATE_ENGAGEMENT`, else the LLM port's first. The task file imports none of the module's registries (index, events, ids, errors), and the module never imports it: hosts load it from the sources (core/packages/ai README "Declaring a task"), and `rateEvents` takes it from the agent registry.
- **Prompt:** `prompt.v1.md`, the system prompt. The data blocks, in order: `<offer>` (Company Knowledge's one-liner, products and pain points, onboarding's `readCompanyKnowledge`) and `<events>` (up to `RATE_BATCH_SIZE`, 10, each `{ index, kind, role, words, post }`: `role` `author`, `comment` or `reaction`; `words` the person's own text, the evidence's excerpt; `post` the evidence's `post_excerpt`; both scrubbed by `domain/rate/scrub.ts`: links, emails, phone numbers and the engager's name as placeholders). Never a name, a profile URL, a headline, a company or a member reference. A changed prompt is a new file, `prompt.v2.md` with `promptVersion: 2`, and runs the evals.
- **Schemas:** `schemas/rate-engagement.ts`. The output: `ratings`, each `{ index, relevance, rationale, intentClass }`: `relevance` 0 to 1, `rationale` one line of at most 200 characters, `intentClass` one of qualification's `INTENT_CLASSES` (`RATE_CLASSES`, checked against them by `tests/rate.test.ts`), or null for an event without the person's words. A value off the list or the bounds fails the schema; code clamps nothing.
- **Gate:** `ratings` (`domain/rate/checks.ts`): each event of the input rated exactly once, no other index, and a class exactly when the event has words. A failed schema or gate is retried once, the failure in `<validation_error>`, then the call is `ai_failed`, and the batch stays unrated.
- **Evals:** `core/packages/ai/evals/signals.rate-engagement/`, thirty synthetic events on two offers, five injections in the words and the post, five off-topic hits of an offer's keyword, and each class at least twice: `pnpm -F ai eval signals.rate-engagement`. Six batches; each case expects what a good model answers, each event its band (`high`, relevance 0.6 or more; `low`, 0.3 or less) and its class, so the same cases run live (`EVAL_LIVE=1`, by hand) after a prompt change. `outcome` 1 and `fails_safe` 1 (the two injection batches: every event in its band and of its class, or `ai_failed`), `classes` and `relevance` 0.8, the shares. On the fake, two cases answer invalidly first, to test the retry: a class on an event without words (the gate) and plain text (the schema).
