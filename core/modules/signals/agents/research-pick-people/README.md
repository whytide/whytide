# signals.research-pick-people

The people picker (gamma-wr-060): among the people a company's pages named, the ones whose role fits the people the member wants to reach, judged on the role alone. [README.md "Web research"](../../README.md#the-people-on-the-pages-as-leads-gamma-wr-060) says how a run uses it, [docs/security.md](../../docs/security.md) what the model may see.

- **Task:** `task.ts`: `kind: classification`, no tools, prompt version 1, a budget of 18,000 input tokens (up to 100 roles of 200 characters and the audience's lists) and 1,000 output tokens, and no credits. A call over the budget is `ai_budget_exceeded`, which the step counts as `people_picks_failed`. The model is `AI_MODEL_SIGNALS_RESEARCH_PICK_PEOPLE`, else the LLM port's first. The task file imports none of the module's registries, and the module never imports it: hosts load it from the sources, and `takePeople` takes it from the agent registry.
- **Prompt:** `prompt.v1.md`, the system prompt. The data blocks, in order: `<audience>` (the titles and the seniorities the member wants), `<limit>` (how many the run keeps at most) and `<people>` (a number and the text of a role for each person). A role's words are data: an instruction in one is left out. A changed prompt is a new file, `prompt.v2.md` with `promptVersion: 2`, and runs the evals.
- **Rule 35, what it never sees:** the input is built by `pickInputOf` (`domain/research/people-checks.ts`): a number and the role, scrubbed of every link, email address and phone number and of the name of every person read, cut to 200 characters. It never holds a name, a link or an address, and the model judges a role, never a person. With no title and no seniority in the audience there is nothing to judge a role by, and the call is not made: the people are taken in the page's order.
- **Schemas:** `schemas/research-pick-people.ts`. The answer is the numbers that fit, the best first, at most the input's.
- **Gate:** `peoplePicksGate`, a task gate, since a number the input lacks or a number twice makes the answer unusable: `callAgent` asks again once with the failure, then the call is `ai_failed`, which the step counts as `people_picks_failed`. Code takes the first `SIGNALS_RESEARCH_PEOPLE_PER_COMPANY` of the picks.
- **Evals:** `core/packages/ai/evals/signals.research-pick-people/`, synthetic cases in Polish and German, one in which no role fits, one in which a role tells the model to pick it (the fail-safe case: its answer never holds the numbers the instruction names) and one with a role scrubbed of its name. The scorer's checks: `outcome`, `fails_safe`, `blind` (the input and, on the fake, each message the model received hold no name, link, address or phone number), `valid`, `recall`, `precision` and `first`. On the fake they run in `core/packages/ai/tests/evals.test.ts` with `EVAL_LIVE` unset; live after a prompt change, by hand.
