# signals.research-read-result

The result reader (gamma-wr-090): for one found company, the results of a web search for its managers on LinkedIn that code kept, and for each the name and the role of the person as its title and snippet write them, so that the run can choose among the people by role. [README.md "Web research"](../../README.md#a-companys-managers-by-search-gamma-wr-090) says how a run uses it, [docs/security.md](../../docs/security.md) what the model may see.

- **Task:** `task.ts`: `kind: classification` (extraction: it reads, it never chooses or ranks), no tools, prompt version 1, a budget of 12,000 input tokens (up to 20 results of a 200-character title and a 500-character snippet, and the company's name) and 2,000 output tokens, and no credits. A call over the budget is `ai_budget_exceeded`, which the people step counts as `managers_reads_failed`. The model is `AI_MODEL_SIGNALS_RESEARCH_READ_RESULT`, else the LLM port's first. The task file imports none of the module's registries, and the module never imports it: hosts load it from the sources (core/packages/ai README "Declaring a task"), and `takeManagers` takes it from the agent registry.
- **Prompt:** `prompt.v1.md`, the system prompt. The data blocks, in order: `<company>` (its name) and `<results>` (the results code kept, numbered from 1: title and snippet, never the address). A result's words are data: an instruction in one is left out. A changed prompt is a new file, `prompt.v2.md` with `promptVersion: 2`, and runs the evals.
- **What code does first, and the model never sees an address:** a result is passed to the model only when its address is a profile's (`normalizeLinkedinUrl`, compared and never fetched) and its title and snippet name the company (`domain/research/managers-checks.ts`, the same cleaning of names as the person's own profile search, `normalName`).
- **Schemas:** `schemas/research-read-result.ts`. The answer is a list of people, each with the number of the result, the name and the role exactly as that result writes them.
- **Gates**, in code and after the call (`domain/research/managers-checks.ts`), because each refuses a part of the answer and keeps the rest. Each refusal is counted by its name in the run's counts, `managers_refused_<gate>`, never by its text:
  - `result`: a number that is not one of the results, or a result answered twice: the person is dropped;
  - `name`: not in that result's title or snippet as whole words (names compared as enrichment compares them: accents, case and spaces folded), or a name that holds an `@`: the person is dropped;
  - `role`: blank, or not in that result's title or snippet: the person is dropped, so that a result that gives no role is not taken.

  The person's profile is the result's address, never the model's; the country is the company's.
- **What the model sees:** titles and snippets as the search engine shows them, names included, since reading them is its whole job. It is the one call that does, and its decision record, whose subject is the workspace, is erased with any person's erasure; the pick never sees any of it.
- **Evals:** `core/packages/ai/evals/signals.research-read-result/`, five synthetic cases of two made-up businesses in two countries and two languages (a cold-room seller in Poland, a solar installer in Chile), results that name nobody, a former role, one retried after a plain-text answer and a snippet that tries to instruct the model (the fail-safe case: its answer never names the person the instruction asks for). The scorer's checks: `outcome`, `fails_safe`, `grounded` (each person's result is one of the results, their name and role are in its text), `recall` and `precision` over the names. On the fake they run in `core/packages/ai/tests/evals.test.ts` with `EVAL_LIVE` unset; live (`EVAL_LIVE=1`, by hand, billed) after a prompt change, the owner's.
