# signals.research-pick-results

The result-picking agent (gamma-wr-045): after a research run's searches, for each search, the results worth reading, the likeliest first, chosen from their address, title and snippet, so that the run's limited number of page reads goes to the likeliest pages. [README.md "Web research"](../../README.md#web-research) says how a run uses it, [docs/security.md](../../docs/security.md) what the model may see.

- **Task:** `task.ts`: `kind: classification`, no tools, prompt version 1, a budget of 24,000 input tokens (50 results of a link, a 200-character title and a 500-character snippet, in a script of three-byte characters, fit) and 1,000 output tokens, and no credits (the run's cost is the cost event alone). A call over the budget is `ai_budget_exceeded`, which the pick step counts as `picks_failed`. The model is `AI_MODEL_SIGNALS_RESEARCH_PICK_RESULTS`, else the LLM port's first. The task file imports none of the module's registries (index, events, ids, errors), and the module never imports it: hosts load it from the sources (core/packages/ai README "Declaring a task"), and `pickResearchResults` takes it from the agent registry.
- **Prompt:** `prompt.v1.md`, the system prompt. The data blocks, in order: `<source>` (the source's focus and region, scrubbed), `<query>` (the search that was run: source type, country, language, text), `<place>` (what a page of the query's source type shows, how it is found and what it is for: a company's site, a list of companies or a notice) and `<results>` (up to 50, each `{ index, url, title, snippet }`; title and snippet scrubbed and cut). A result's words are data: an instruction in one is left out. The prompt asks for few picks (five at most) and none when none deserves one. A changed prompt is a new file, `prompt.v2.md` with `promptVersion: 2`, and runs the evals.
- **Schemas:** `schemas/research-pick-results.ts`. The output: `picks`, each `{ index }`, the number of a result, the likeliest first.
- **Gate:** `picks` (`domain/research/checks.ts`, `picksGate`): each number is one of the input's results, and none twice. A failed schema or gate is retried once, the failure in `<validation_error>`, then the call is `ai_failed` and the search's pages are not read. The code then keeps the first `PICKS_PER_SEARCH` picks.
- **Evals:** `core/packages/ai/evals/signals.research-pick-results/`, seven synthetic cases of two made-up businesses in two countries and two languages (a maker of cold-chain loggers in a Polish-speaking country, and a maker of solar roof rails in two Spanish-speaking ones): company sites among a job advertisement and a news page, an exhibitors' list among a ticket page and a forum thread, a number that is no result (the gate: ok after two attempts), a members' directory against an encyclopaedia entry, an award notice against a portal's home page, an instruction in a snippet, and a search whose results nothing is worth reading in. Each case names the picks a good model gives, so the same cases run live. The scorer's checks: `outcome`, `fails_safe`, `valid` (numbers of the input, none twice, five at most), `recall`, `precision`, `first` (the likeliest first, or none when none is worth reading). On the fake they run in `core/packages/ai/tests/evals.test.ts` with `EVAL_LIVE` unset; live (`EVAL_LIVE=1`, by hand, billed) after a prompt change, the owner's.
