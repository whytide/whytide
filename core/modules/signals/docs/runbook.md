# signals: runbook

- **Settings**: `SIGNALS_MAX_ENABLED_SOURCES`, `SIGNALS_MAX_TRACKED_PER_ACCOUNT` and each kind's lookback, 30 days at most (README "Settings"); a value off the rules stops the api's start with `config_invalid`, `details.block` `modules/signals`, `details.variables` naming the variable.
- **Logs and metrics**: the worker's activity lines, by activity name and code; `signals.runs` by `outcome` and `code` and `signals.candidates` by `kind`, on the dashboard `whytide-signals`. A run's history is in Temporal, workflow type `signals_run`: ids, the post URL and keys only.
- **The daily runs** (gamma-p5-040): every hour (`signals.daily_runs`, `DAILY_RUNS_TICK_MINUTES`, paused while `WORKER_SCHEDULES=off`), `signals_daily_runs_tick` writes a run of each daily source due; its result is `{ workspaces, started }`. A source that does not run: it already ran on its account's quota day (any run started that day counts: its save's, Run now's, a tick's), a run of it is open, the account is outside its working hours, has `SIGNALS_READS_KEPT_FOR_SENDS` or fewer reads left (20 unset) or is stopped (a kill switch, the pause, `retry_at`), or is not connected; or its agent is paused (paused-agent-sources), by a member or for its owner's removal: resume the agent on its page, and the source runs from its next due time. A failed tick names a workspace's failure (its code in the worker's activity line); the other workspaces' runs were written, and the next tick, an hour later, tries again. A run that ends `done` with `counts.budget_reached` read its share of the day, or its pages half of it (the page limit) and its profiles the rest: the runs panel says so, and the next day's run reads on from the same cut. To read more today, Run now takes a share of what is left.
- **The reduction**: daily at 03:00 UTC (`signals.evidence_reduction`, paused while `WORKER_SCHEDULES=off`), one line `signals: evidence reduced` per workspace with `reduced_count`. To reduce a workspace now: `pnpm evidence:reduce --workspace <id or slug>`, which prints `evidence_reduced: <count> in <workspaceId>`; `workspace_not_found` names a slug no single workspace has: pass the id. A failed tick (`signals_evidence_reduction_tick`) is tried again the next day; the rows it missed are reduced then.
- **Failure modes**:
  - The start fails with `module_invalid` for `signals`, caused by `signal_kind_duplicate`: two folders declare one kind, `details.sources` names both files; rename one. Caused by `signal_kind_invalid`: a kind's name is not snake_case.
  - The start fails with `module_invalid` for `signals`, caused by `ERR_MODULE_NOT_FOUND` for `dist/sources/registry.generated.js`: the module was compiled without its list (a host's `tsc -b` alone, as the worker's `modules:build`); `pnpm -F @whytide/signals build`, or the api's, writes it.
  - `signal_sources_limit` (400) for a tester: the source's group, its agent's sources or those in no agent (a create's), has `SIGNALS_MAX_ENABLED_SOURCES` enabled (gamma-p5-045); disable one of them, link a source in no agent to an agent on its page, or raise the setting. `signal_tracked_limit` (400): the sender account has `SIGNALS_MAX_TRACKED_PER_ACCOUNT` enabled competitor and creator sources; disable one of them, or add the source on another account.
  - `signal_kind_unknown` (400) on a PATCH of a stored source: its kind's folder was removed while its rows remain.
  - A run stays `waiting`: its account is outside its working hours, or, for a run started before gamma-p5-040, out of reads for the day; it resumes at the refusal's `retryAt`. Check the account's `daily_read_cap`, working hours and time zone (linkedin). To end it now, Stop on the Sources screen (`POST …/runs/{runId}/stop`); the worker's line `signals: a run's workflow cancelled` names the workflow, `outcome` `not_open` when no open workflow had that id. That is how a run the schedule started before fix-run-stop shows: it has no `workflow_id`, so Stop misses it; cancel it in Temporal, `temporal workflow cancel --workflow-id <id>`, its id `signals-<sourceId>-<time>` from `temporal workflow list --query "WorkflowType='signals_run'"`.
  - A run `failed` with `linkedin_account_disconnected` (`signals.source_blocked`): reconnect the account; the next fire time or `POST …/run` runs again. `insufficient_credits`: the organization's balance; `signal_post_not_found`: the post is gone or the account cannot see it; `linkedin_not_found` (a competitor or creator run): the page or the profile is gone, renamed, or out of the account's sight, so check the source's link and add the source again with the right one; `activity_failed`: a step failed past its attempts, the worker's activity line names it; `linkedin_rate_limited`, `linkedin_provider_error` and `linkedin_error_unmapped`: the provider failed past its attempts. The runs panel words each code.
  - `signal_agent_paused` (409) on `POST …/run`: the source's agent is paused (paused-agent-sources); resume it on the agent's page (one paused because its owner left: by that owner alone, once a member again), or unlink the source. A run written before the pause ends `cancelled` at its start, with no read.
  - `signal_run_open` (409) on `POST …/run`: one of the source's runs is `running` or `waiting`; wait for its end. A row left `running` or `waiting` with no open `signals_run` workflow in Temporal (one terminated there, which skips its end step) keeps refusing: end it by hand, as the owner, `UPDATE signal_runs SET status = 'failed', error = 'activity_failed', finished_at = now() WHERE id = '<run_id>' AND status IN ('running', 'waiting');`.
  - A source with no schedule (saved before alpha-p8-020, or its created event failed): disable it, then enable it; the enable makes its schedule.
