# icp: flows

- **Reading** (`GET …/icp`, `GET …/icp/criteria`): the api host's guards, then the handler in the request's tenant run. The first read of a workspace inserts its default audience with `ON CONFLICT DO NOTHING`, then the six default criteria: a second first read at the same time waits on `icps_default` for the first one's commit, skips its insert and answers the same row.
- **Audiences** (`…/icp/audiences`, gamma-p3-020): the list makes the default first; a create takes the workspace's advisory lock until its run commits, counts the audiences, the default included, and past `ICP_MAX_AUDIENCES_PER_WORKSPACE` (10 unset) answers 409 `icp_audience_limit`, else inserts the audience with the six default criteria. `…/audiences/{icpId}` and its `/criteria` read and save that audience as the ICP's routes do the default; an id another workspace holds is not found in the run's workspace: 404 `icp_not_found`.
- **Saving the ICP** (`PUT …/icp`): the body's schema checks the lengths and counts (400 `validation_failed`); `saveIcp` checks the closed lists (400 with the list's code, nothing written), locks the ICP's row, compares the targeting with what is stored and writes; on a targeting change it moves the version and writes `icp.audience_updated` to the outbox in the same transaction, and `icp.updated` for the default, which the worker delivers.
- **Saving the criteria** (`PUT …/icp/criteria`): six rows, each key once (the schema); the weights sum to 100 (`icp_weights_must_sum_100`); `saveCriteria` locks the ICP's row, as `saveIcp` does, then updates each row by its key, none added or removed; the version stays.
- **Editing on the screen** (`/w/{ws}/icp`): the page reads the audiences, then the one `?audience=` names, else the default, and its criteria; Save sends that audience's `PUT …/audiences/{icpId}/criteria`, then, once it passed, `PUT …/audiences/{icpId}`, from the browser through the web's `/api` rewrite; the answers replace the form's values (trimmed, without duplicates, countries in code order) and the version badge. An error answer stops the save and shows next to the field it names.
- **Scoring** (alpha-p6): qualification's activity calls `readIcpForScoring(workspaceId)` inside its own tenant run: the default.
- **Drafting** (`pnpm icp:draft`, README "The draft"): the script's tenant run checks the ICP has no targeting (unless `--replace`), then `requestDraft` marks it `drafting` under a new run and writes `icp.draft_requested`, in one transaction. The worker delivers the event; the subscriber starts `icp_draft_profile`, whose activity reads the Company Knowledge and the brief, calls the model outside any tenant run and writes the pending draft, or the failure, while the run is still the latest. The script reads the ICP every two seconds, prints the proposal and saves it through `acceptDraft`, as the screen does.
- **Drafting on the screen** (`/w/{ws}/icp`, README "The screen"): the page reads `GET …/icp/draft` with the ICP; Draft sends `POST …/icp/draft` with the brief and an Idempotency-Key, whose `requestDraft` and event are the script's; the card then reads `GET …/icp/draft` every two seconds, for ten minutes at most, until the worker wrote the proposal or the failure. Use this draft sends `POST …/icp/draft/accept` with the proposal's run: `acceptDraft` locks the ICP's row, checks the drafted proposal is that run's, the targeting (`replace`) and the PUT body's schema, saves through `saveIcp`, which moves the version and writes `icp.updated` on a targeting change, and ends the draft, in one transaction; the form shows the saved ICP. Discard sends `POST …/icp/draft/discard`, which ends the draft alone.
- **Drafting automatically** (README "The automatic draft"): the worker delivers onboarding's `onboarding.company_knowledge_updated`; icp's subscriber, in the delivery's tenant run, locks the default's row and, while Company Knowledge has a content field, the default no targeting and no draft running or waiting, requests a draft without a brief, marked automatic, as `requestDraft` does. The drafter's write then saves the proposal through `saveIcp` and ends the draft, in one transaction, while the ICP is still empty; else the proposal waits for review.
