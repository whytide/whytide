# icp: flows

- **Reading** (`GET …/icp`, `GET …/icp/criteria`): the api host's guards, then the handler in the request's tenant run. The first read of a workspace inserts its ICP with `ON CONFLICT DO NOTHING`, then the six default criteria: a second first read at the same time waits for the first one's commit, skips its insert and answers the same row.
- **Saving the ICP** (`PUT …/icp`): the body's schema checks the lengths and counts (400 `validation_failed`); `saveIcp` checks the closed lists (400 with the list's code, nothing written), locks the ICP's row, compares the targeting with what is stored and writes; on a targeting change it moves the version and writes `icp.updated` to the outbox in the same transaction, which the worker delivers.
- **Saving the criteria** (`PUT …/icp/criteria`): six rows, each key once (the schema); the weights sum to 100 (`icp_weights_must_sum_100`); `saveCriteria` locks the ICP's row, as `saveIcp` does, then updates each row by its key, none added or removed; the version stays.
- **Editing on the screen** (`/w/{ws}/icp`): the page reads both; Save sends `PUT …/icp/criteria`, then, once it passed, `PUT …/icp`, from the browser through the web's `/api` rewrite; the answers replace the form's values (trimmed, without duplicates, countries in code order) and the version badge. An error answer stops the save and shows next to the field it names.
- **Scoring** (alpha-p6): qualification's activity calls `readIcpForScoring(workspaceId)` inside its own tenant run.
- **Drafting** (`pnpm icp:draft`, README "The draft"): the script's tenant run checks the ICP has no targeting (unless `--replace`), then `requestDraft` marks it `drafting` under a new run and writes `icp.draft_requested`, in one transaction. The worker delivers the event; the subscriber starts `icp_draft_profile`, whose activity reads the Company Knowledge and the brief, calls the model outside any tenant run and writes the pending draft, or the failure, while the run is still the latest. The script reads the ICP every two seconds, prints the proposal and saves it through `saveIcp`, which moves the version and writes `icp.updated` on a targeting change.
