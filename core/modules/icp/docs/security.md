# icp: security

Read before changing the module ([security §8](../../../../docs/rules/security.md#8-conduct)).

- **Tenancy**: every query goes through the caller's tenant run (`tenantClient`), scoped to its workspace, which comes from the URL, never from a body; `readIcpForScoring` refuses another workspace than its run's (`tenant_mismatch`). An audience's id is looked up in the run's workspace only, so another workspace's is 404 `icp_not_found` on every route that takes one, the draft's `?icpId=` included. `tests/tenancy.test.ts` registers `icps` and `criteria` in the two-workspace harness and checks the query with `assertScoped`.
- **Who may do what**: `icp.read` and `icp.write` (Owner, Admin, Member) on every route, and on every write the row's check (gamma-p6-015): `lockedIcpId` asks platform's `canWriteOwned`, so a member writes the audiences they created and a holder of `icp.manage` (Owner, Admin) every one; another member's audience, the default and a row whose `created_by` is null or `system` are 403 `forbidden` to a Member, before anything is written. A service's run writes every one.
- **What the AI sees**: titles, industries, must-haves and disqualifiers reach the assessment prompt (alpha-p6-020) as data in delimited blocks, never instructions ([security §6](../../../../docs/rules/security.md#6-ai)). Their limits keep the prompt bounded: 50 and 30 items of 100 characters, 1,000 characters per text.
- **The drafter** (`icp.draft-profile`) sees Company Knowledge's content fields and the admin's brief in the `<company>` and `<brief>` blocks, data, never instructions; no person's data. Its answer is checked by the schema and the gate, then shown to a member on the screen or an engineer in the script, and only the member's Use this draft, the script's save or the automatic draft's save into an ICP still without targeting writes a field, through `saveIcp` and the PUT body's schema. The event and the workflow carry ids; the brief, the sources and the draft stay out of every log line and of the script's output, but for the proposal it prints.
- **The screen** calls the api from the browser, through the web's `/api` rewrite, with the session cookie and the api's origin check; it holds no secret and keeps nothing in the browser. The draft's answers carry the proposal, its prompt version and its run, never the brief, the model or the decision record; Use sends the run back, so that it saves only the proposal the member saw; the draft's POSTs are idempotent, so that a retried Use re-scores the leads once.
- **Limits**: `ICP_MAX_AUDIENCES_PER_WORKSPACE` audiences per workspace (10 unset, 1 or more with no maximum; README "Settings"), counted under the workspace's advisory lock, so that two creates at once cannot pass it.
- **Personal data**: none stored; `created_by` is a user's id. The events carry ids and a version; an error's details carry paths and a sum, never a value.
