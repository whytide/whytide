# icp: data

Two tenant tables in `core/packages/db/prisma/schema/icp.prisma`, created by the migration `20261022151000_icp_initial`; `20261029021500_icp_draft` adds the draft's columns, `20261102110054_icp_audiences` the audiences' (gamma-p3-020), `20261106062311_icp_draft_automatic` the automatic draft's flag (icp-auto-draft). The ids are `icp_<ULID>` and `crit_<ULID>`, a draft's run `idrun_<ULID>` (`ids.ts`); the time is `timestamptz`.

| Table | Id | Columns | Keys | Scope |
|---|---|---|---|---|
| `icps` | `icp_` | `workspace_id`, `name`, `titles`, `seniorities`, `industries`, `size_ranges` and `countries` (text arrays), `must_haves`, `disqualifiers`, `version` (from 1), `is_default` (true by default), `created_by` (a user's id, or `system`; null before audiences), `updated_at`; the draft's: `draft_status` (`none`, `drafting`, `drafted`, `failed`), `draft_error` (a code), `draft_run_id`, `draft_brief` (the brief, empty when none), `draft_automatic` (true while the latest run is the automatic one, which saves itself into an empty ICP), `pending_draft` (JSON: the proposed fields, the model, the prompt version, the decision record's id) | `icps_default` `(workspace_id)` unique where `is_default`, a partial index written in the migration: one default per workspace; index `(workspace_id, updated_at)` | tenant |
| `criteria` | `crit_` | `workspace_id`, `icp_id` (references `icps`, deleted with it), `key`, `weight`, `is_must`, `enabled` | `(workspace_id, icp_id, key)` unique | tenant |

No foreign key to `workspaces`: Prisma would need the opposite relation in `tenancy.prisma`. The closed lists and the limits are checked by the commands, the only writer, not by the database; so is the number of audiences, `ICP_MAX_AUDIENCES_PER_WORKSPACE` at most (10 unset; README "Settings"), under the workspace's advisory lock. The migration is expand-first: it drops the unique key on `workspace_id`, and `is_default` defaults to true, so a row the release before it inserts is the default.

Who writes a row (gamma-p6-015): the member `created_by` names, and a holder of `icp.manage`. The default, whoever's first read created it, and a row whose `created_by` is null (made before audiences) or `system` (a service's) belong to the workspace: only `icp.manage` writes them, and a service's run. No backfill was needed for that.

Personal data: none; the ICP describes a market, not a person, and the brief what the admin sells to; `created_by` is a user's id, a plain reference. The draft's columns are overwritten by the next request; an accept, a discard or the automatic save sets `draft_status` back to `none`, `draft_automatic` to false, and clears `draft_error`, `draft_run_id` and `pending_draft`, keeping `draft_brief`; the decision record keeps the call (core/packages/ai). Retention: configuration, kept with the workspace; nothing is deleted in alpha.
