# enrichment: data

Made in migration `20261113152938_enrichment_initial`, schema file `enrichment.prisma`.

- **`enrichment_runs`** (`erun_`, tenant: `workspace_id` on every row): `person_id` and `company_id` (contacts' ids, plain, no foreign key across modules), `trigger` (enum `enrichment_trigger`), `request_key`, `status` (enum `enrichment_run_status`, default `queued`), `skip_reason`, `wanted` and `filled` (field names), `sources_tried` (jsonb `[{ source, outcome, code, filled, ms }]`: names, codes and field names, never a value), `created_at`, `started_at`, `finished_at`.
  - Unique `(workspace_id, request_key)`: a key makes one run.
  - Indexes `(workspace_id, person_id, created_at)` for a person's last run, `(workspace_id, company_id, finished_at)` for a company's recent runs.
  - No value of the person or the company: those stay in contacts, with their provenance.
- **`source_usage`** (`susage_`, global: no `workspace_id`, no personal column): `source`, `period_start` (text, `YYYY-MM-DD`, the period's first day in UTC), `period` (enum `source_usage_period`: `day`, `month`), `used`, `spent`, `updated_at`.
  - Unique `(source, period_start)`: one counter per source and period for the whole instance.
  - `app` reads, inserts and updates, never deletes (`REVOKE DELETE`); CHECK `source_usage_used`: `used >= 0`.
  - Rows of past periods stay: a few rows a source a day, nothing personal.

**The eraser:** `erasePerson(personId)`, registered in privacy's `domain/erase/erasers.ts` with no dependency, deletes the person's runs, counted as `enrichment.enrichment_runs`. The counters stay. A run erased while it works finds no row: its steps write nothing more.

**gamma-en-080**, migration `20261113183319_enrichment_email`:
- **`contact_points`** (`cp_`, tenant): `person_id`, `kind` (`work_email`, `personal_email`), `value` (`/// pii: personal`, the address), `verification`, `verified_at`, `confidence`, `source_class`, `provider`, `acquired_at`, `legal_basis` (`legitimate_interest`), `status` (`active`, `bounced`, `opted_out`). Unique `(workspace_id, value)`: one address on one person; index `(workspace_id, person_id)`.
- **`enrichment_requests`** (`enr_`, tenant): `person_id`, `trigger` (enum `email_lookup_trigger`), `request_key`, `status`, `reason` (why it ended without an address; while a lookup of the lead's own sources runs, its plan's reason, gamma-en-100), `attempt`, `providers_tried` (jsonb `[{ source, step, outcome, code, ms }]`, `step` one of `find`, `candidate`, `verify`: names and codes, never an address), `contact_point_id`, `credit_usage_id`, `error_code`, `credits_charged`, `finished_at`. Unique `(workspace_id, request_key)`.
- **`enrichment_cache_entries`** (`ecache_`, tenant): `key_hash` (sha256 of the normalised first name, last name and domain), `kind` (`email`, `negative`), `value` (`/// pii: personal`), `verification`, `reason`, `provider`, `retrieved_at`, `expires_at`, `person_id`. Unique `(workspace_id, kind, key_hash)`.
- **`email_domain_statuses`** (`eds_`, global, no personal column): `domain` (unique), `catch_all`, `provider`, `checked_at`, `expires_at` (30 days): a catch-all domain spares every workspace a vendor call. Recorded only when the address the verifier called `catch_all` sits at the person's current company domain itself: never a former employer's domain, never a subdomain.
- The candidates' files, `raw/enrichment/<requestId>/<n>.json` in the workspace's folder, are deleted at the settle; the files port drops a `raw/` file after 72 hours anyway.

The eraser also deletes the person's contact points, requests and cache entries (`enrichment.contact_points`, `enrichment.enrichment_requests`, `enrichment.enrichment_cache_entries`). A domain's status names no person and stays.

**gamma-wr-100**, migration `20261119040000_enrichment_phones` (expand only): the kind `phone` joins `contact_point_kind`; `contact_points.verification` and `verified_at` become nullable, and the CHECK `contact_points_email_verified_check` keeps both required for `work_email` and `personal_email`; the new nullable column `page_url` holds the address of the page a value came from (a phone's page, without its query). A phone row: `value` the number as `cleanPhone` leaves it (`/// pii: personal`, the same column as an address), no `verification`, no `verified_at`, class `web_page`, provider `research`, `legal_basis` `legitimate_interest`. The unique key `(workspace_id, value)` keeps one number on one person; the eraser deletes a phone with the person's other contact points (counted in `contact_points`).

**gamma-en-085**, migration `20261113203623_enrichment_email_pattern`: `email_domain_statuses` gains `pattern` (text, null: one of the fixed names of `domain/email/constants.ts`, `{first}.{last}` and the like, never an address), `pattern_source` (enum `email_pattern_source`: `website`, `verified`) and `pattern_checked_at`; the CHECK `email_domain_statuses_pattern` holds the names and sets the three together or none. A pattern is read for 180 days (`PATTERN_DAYS`). A row made for a pattern alone has `catch_all` false, `provider` its source (`website` or `verified`) and `expires_at` its writing. The table stays global, with no personal data: a domain and a pattern's name. New contact points' classes: `lead_reply`, `website`, `pattern`.

**gamma-rf-030**, migration `20261114162614_enrichment_domain_patterns`: **`email_domain_patterns`** (global: no `workspace_id`, no personal column), one row per company domain and address pattern, keyed by `(domain, pattern)`: `verified_count` (the verified addresses that fitted it, 0 or more), `last_verified_at` and `site_seen_at` (null until a verified address, or the company's site, gave it), `created_at`.
- Hand-written CHECKs: `email_domain_patterns_pattern`, the pattern one of the fixed names (the list of `email_domain_statuses_pattern`); `email_domain_patterns_seen`, at least one of the two times; `email_domain_patterns_count`, the count above 0 exactly when `last_verified_at` is set. `app` reads, inserts and updates, never deletes (`REVOKE DELETE`).
- Each write is one `INSERT … ON CONFLICT … DO UPDATE`: a new verified address adds 1 to its pattern's count and sets `last_verified_at`; a site's pattern sets `site_seen_at` and never changes a count. A pattern last verified and last seen more than `PATTERN_DAYS` (180) ago is not read, and its row stays.
- The migration copied each domain's pattern from `email_domain_statuses`: a `verified` one with a count of 1 and its time, a `website` one with a count of 0 and its time. `email_domain_statuses`' `pattern`, `pattern_source` and `pattern_checked_at` stay, neither read nor written any more; dropping them is a later migration, on the owner's approval. `email_domain_statuses` keeps the catch-all status.
- No personal data: a domain, a pattern's name, a count and two times. The count is the instance's: the same address kept in two workspaces counts twice. The eraser leaves it.

**gamma-wr-070**, migration `20261119031500_enrichment_lookup_at_find`, expand only: the enum `email_lookup_trigger` gains `found` (a lead research found), and **`enrichment_requests.printed_address`** (text, null, `pii: personal`) holds the address a company's page printed with the person while a lookup `found` runs, verified first, and is emptied when the lookup ends (the settle, the prepare's free ends); no index, no CHECK, never in a workflow input, a result, an event, `providers_tried` or a log line. A new contact point's class: `page_printed` (provider `page`). The eraser deletes the request with the person.
