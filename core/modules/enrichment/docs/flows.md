# enrichment: flows

Inputs, results and events carry ids, source names, field names and codes; the facts go from the source's activity to contacts.

- **The tick** (`enrichment_tick`, global): the schedule `enrichment.tick` every `ENRICHMENT_TICK_MINUTES`, a tick skipped while one runs. Its activity lists the workspaces (tenancy's `listWorkspaceIds`), asks each in a run of its own, as the service principal `enrichment`, for one held lead (contacts' `leadsHeldForEnrichment`), and starts `enrichment_batch` for each that has one, as `enrichment.batch:<workspaceId>`, one at a time. A workspace that fails leaves the others started; the tick then fails with its code.
- **The batch** (`enrichment_batch { workspaceId }`): the held leads, oldest first, `ENRICHMENT_BATCH_SIZE` at most. For each, `enrichment_open_run` writes its run (`new_lead`, key `new_lead:<personId>`); a key that has a run already makes none and releases the hold. Each run is a child workflow, `enrichment.run:<workspaceId>:<runId>`, one after another. Answers `{ leads, runs, failed }`.
- **A request:** `requestEnrichment` writes the run (`request`, key `request:<key>`) and publishes `enrichment.run_requested { runId }` in the caller's transaction; the worker's subscriber starts `enrichment_run` with the same id, so a redelivery starts none. The lead page's "Enrich now" asks through `POST …/enrichment/leads/{personId}` (gamma-en-055): its `Idempotency-Key` is the request's key, so the same key answers the same run; the panel then reads `GET …/enrichment/leads/{personId}` every 3 seconds, for 60 at most, while the run is `queued` or `running`.

## The run

`enrichment_run { workspaceId, runId }`:
1. `enrichment_prepare` (`db`): reads the run and the person, and the company through contacts' `refreshCompany` (gamma-rf-010: the company linked to its shared company if it was not, a key it lacks taken from its organization's row or the shared company, and the facts the shared company holds already read as filled, so no source is asked for them, unless they are old: a fact whose stamp is older than `ENRICHMENT_FACT_DAYS` when the run starts is wanted again, gamma-rf-020); under a transaction lock on the workspace's company (`pg_advisory_xact_lock`), reads its runs done within `ENRICHMENT_COMPANY_RETRY_DAYS` and another run working on it (started within 60 minutes). It writes the run `running` with its wanted fields and the reason it skips the company, if any: `no_company` (neither a company nor a company name), `enriched_recently` (a new lead's run, the company tried for every field wanted now), `company_running`. It answers the plan: the sources that fill a wanted field, in order, with no value.
2. The pass, below.
3. `enrichment_finish` (`db`): the run `done`, or `failed` when its own steps failed; `finished_at`; contacts' `releaseEnrichmentHold([personId])`. A failure of the prepare or of the pass's record ends the run through the same finish, `failed`.

## The pass

The workflow takes the first source, from the top, not asked yet, that has one of its inputs and fills a field still open. Its step (`enrichment_source`, `enrichment_source_ai` or `enrichment_source_db`, by its activity kind):
1. reads the run's input in a run of its own: the company's page, domain, name and country, or the person's location text, with the run's workspace and the person's company ids;
2. counts the call (`reserveCall`, on the global table); a refusal records `allowance_spent` and makes no call;
3. calls the source outside any transaction, with `context.tenant` for its own runs of the workspace; a skip in its own word is recorded as its outcome;
4. in one tenant run, under the run's lock, writes the facts for the open fields that are empty or old (gamma-rf-020) through contacts' `upsertCompany` (or `recordPersonCountry`), with the source's class and the provider that answered, and records the outcome. A run that ended takes nothing; one that recorded the source already (a late answer past the step's timeout, a `db` step tried again) takes nothing and answers that record. A person with only a company name gets a company made by the page or domain the source brought, linked first; with neither, `no_company_key`. A key another company holds, or that contacts refuses, is written again without the page, then without the domain.

It answers `{ outcome, filled, inputsAdded }`. A source's error is recorded `failed` with its code and one warning, never raised; a `*_allowance_spent` marks the period spent. A step that fails anyway (a timeout, a worker restart) is recorded `failed` by `enrichment_source_failed` with the failure's code, and the pass goes on. A filled domain or page restarts the pass from the top.

## The lookup

`requestLookup` or `requestReverification` (the email step's, or the Email panel's "Find email" and "Verify again", keys `request:<key>` and `reverify:<key>`, gamma-en-081) writes the request and publishes `enrichment.lookup_requested { requestId }`; the subscriber starts `enrichment_lookup { workspaceId, requestId }` as `enrichment.lookup:<workspaceId>:<requestId>:<attempt>`, so a redelivery starts none and a request asked again runs anew.
1. `enrichment_lookup_prepare` (`db`), under the request's lock: the first free end that applies settles it with its event, no call and nothing reserved. Suppressed, `skipped_suppressed`; an active, valid address verified within `ENRICHMENT_EMAIL_VALID_DAYS` (120 unset), `found`; no name, a live cache entry (an address, or `cached_negative`), no verifier with a call left this period (`waiting_allowance`; `source_usage` read before the run). Then the credits reserved, unless every listed source has `anyDomain` (an address the lead gave is free). The company is read through contacts' `refreshCompany` (gamma-rf-010), so a domain its organization or the shared company knows is there. No domain, a catch-all domain or the credits short plan the lead's own sources only, those with `anyDomain` in the list's order, nothing reserved, the reason (`no_domain`, `catch_all`, `insufficient_credits`) kept on the request for the settle; with none listed, or no verifier left, they end there as before: `not_found`, or `waiting_budget` for the credits (gamma-en-100). The request `running`; the plan: the sources, the verifiers' turns and the most candidates, names and numbers only. A re-verification needs its active address and a verifier with a call left, and reserves nothing; a personal address of a lead whose country needs consent, while `ENRICHMENT_PERSONAL_EMAIL_EU_UK` is off, goes to no verifier and ends `not_found` (`personal_needs_consent`), its contact point unchanged.
2. Each source in order, once (`enrichment_find`, `_ai` or `_db` by its kind, one attempt): the person's names and the company's domain read under the lock, the call counted, the source called outside any transaction. Its candidates are dropped or kept (at a catch-all domain, the lead's own addresses at that domain dropped, `catch_all_domain`), each kept one written to its file; the steps go to `providers_tried`, once per source. A failure is recorded with its code and the next source asked.
3. Each kept candidate to the verifiers in turn (`enrichment_verify`, one attempt): the call counted, the lower-case address sent, the verdict written to its file and `providers_tried`. No calls left or a failure: the next verifier. The walk stops at `valid`, `catch_all` on a work address, the most candidates verified, or no source left; a candidate no verifier could check ends it (no verifier left, or every one failed).

## The settle

`enrichment_lookup_settle` (`db`), under the request's lock, once:
- **Valid:** the address kept as a contact point, unless another person holds it (`held_by_other_person`) or the person holds it bounced (`bounced`); the email entry for `ENRICHMENT_EMAIL_VALID_DAYS` (120 unset); the credits committed, or released for an address from a source with `anyDomain`, which the lead gave (gamma-en-100); `enrichment.address_verified { requestId, personId, contactPointId }`.
- **A lookup of the lead's own sources** (its plan's reason on the request): a valid address kept as above, free; any other end the plan's reason, `not_found` or `waiting_budget`, with no cache entry and any reservation released.
- **Any other end:** the credits released; a negative entry for `ENRICHMENT_EMAIL_NOT_FOUND_RETRY_DAYS` (30 unset), except after a provider error, no verifier or `personal_needs_consent`; after `catch_all`, the company's domain recorded for 30 days when the address sits at that domain itself (not a former employer's, not a subdomain); `enrichment.address_missing { requestId, personId, reason }`.
- **A re-verification:** the contact point's verification and time updated; free.
- Then the candidates' files deleted. A cancelled lookup settles `failed` (`activity_cancelled`).

**The lookup at find (gamma-wr-070).** A lookup with the trigger `found` that holds the address a page printed with the person plans one more step, first: `printed` (no source of the list, activity `db`, no outside call, no count). Its find reads the address from the request, lower case, and proposes it as one candidate; the drops are the others' (`other_domain` for an address off the company's domain, which no verifier is asked), and the verifiers, the walk and the settle are unchanged: a `valid` ends the walk before any source, a never-contact address ends `skipped_suppressed`, another person's `not_found`. Class `page_printed`, provider `page`, charged as any found address. A live negative cache entry does not end such a lookup first: its plan is the printed step alone, and any verdict but `valid` ends it `not_found`. The request's `printed_address` is emptied by the settle (a request that is not running, settled by a cancel or a failed prepare, included) and by every free end of the prepare. With the credits short, only the lead's own sources are planned and the printed step is not.

## The lookup for a name (gamma-wr-080)

A name no page keyed is looked up inside signals' people step (`workAddressOfName`, `domain/lookup/name.ts`): no request, no workflow, no raw file. Free gates first (no name or domain, a domain recorded catch-all, no source with `forName`, no verifier with a call left), then the credit reserved as `enr:name:<found company>:<place in the pick>`. Each source with `forName` in order (counted, called outside any run, its candidates dropped as a lookup drops them), each kept candidate to the verifiers in turn, until `valid`, the bound on candidates, or the sources are done. A `valid` address is kept in one tenant run: another person's address ends it, `make(address)` makes the person, the contact point is kept for them, the cache entry and the pattern's count written and the credit committed; a never-contact address, another person's contact point or a `make` that answers null rolls the run back. Any other end releases the credit and leaves nothing but a catch-all domain's row.
