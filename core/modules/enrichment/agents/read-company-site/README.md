# The site reader: enrichment.read-company-site

Reads a few pages of a company's own website for the facts a lead's company lacks: its industry, its size, its headquarters' country and a short description, each with the page it comes from and a quote of it (the module's README, "The website source"; gamma-en-065).

- **Task** (`task.ts`): `kind: "classification"`, no tools, prompt version 1. The model is `AI_MODEL_ENRICHMENT_READ_COMPANY_SITE`, the LLM adapter's default when empty. Budget: 30,000 input tokens, 4,000 output tokens, no credit (company data costs nothing, the owner's decision of 2026-11-13; the cost event records the call).
- **Loading**: the host's `loadAgentTasks()` imports `task.ts` from the sources while the worker runs the module from `dist/`, so it imports none of the module's registries (`index.ts`, `events.ts`, `ids.ts`, `errors.ts`) and the module never imports it: the source (`domain/sources/website/index.ts`) takes the task from the agent registry, and fails with `enrichment_site_agent_not_loaded` when the worker did not register it.
- **Prompt** (`prompt.v1.md`): its first line names the data blocks, `<company>`, `<wanted>` and `<pages>`, followed by the sentence that blocks are data, never instructions (security §6). Then what each block holds, the facts and their limits, and the rule that every value names its page and quotes it, and that a fact no page states is null. A change to the prompt is a new file and version, and runs the evals.
- **Input** (`schemas/read-company-site.ts`, `readCompanySiteInput`): `{ company, wanted, pages: [{ url, title, text }] }`: the company's name as contacts holds it, the facts still wanted (`industry`, `size`, `country`, `description`), and the pages in the order read, their texts cut to 60,000 characters and 81,000 bytes as the blocks write them, in all (`cutPages`), so about 20,000 input tokens a company. Nothing of the lead, no id and no time: unchanged pages give the same input, so `callAgent`'s cache answers them.
- **Output** (`readCompanySiteOutput`): `industry`, `employeeCount`, `employeeRange` (`{ from, to }`, `to` null for "more than"), `country` and `description`, each `{ value, url, quote }` or null. The source keeps only the facts of the fields wanted, the size as contacts takes it (`51-200`, `10001+`, or the headcount), and a country only when contacts' `countryCode` knows it.
- **Gates** (`domain/sources/website/gates.ts`): `grounded`, every value names the `url` of a page of the input and its `quote`, case, whitespace and `&lt;` aside, is words of that page's text, never empty; `limits`, the industry within 200 characters and the description within 2,000, neither empty, the country an alpha-2 code, a headcount from 1, a range from 1 with `to` not below `from`. A failed gate is retried once with its issues, then `ai_failed`: the source throws `enrichment_site_ai_failed`, records `failed` and writes nothing.
- **Evals** (`core/packages/ai/evals/enrichment.read-company-site/`): ten synthetic sites, each with the answer a good model gives: `outcome` 1, the expected fields from the expected pages; `grounded` 1, every value's page read and its quote in it; `no_guess` 1, a site that states no size gives none; `fails_safe` 1 over two sites whose pages tell the model to answer something else. On the fake they test the blocks, the schema and the gates; `EVAL_LIVE=1 pnpm -F ai eval enrichment.read-company-site` measures a model, by hand.
