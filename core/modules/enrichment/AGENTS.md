# enrichment: the brief for a coding agent

1. Read `README.md`, then `docs/concepts.md`, `docs/data.md`, `docs/flows.md`, `docs/security.md` and `docs/runbook.md`. They say what is true now and change in the same merge request as the behavior.
2. The rules: [coding](../../../docs/rules/coding.md), [security](../../../docs/rules/security.md), [delivery](../../../docs/rules/delivery.md). The shape of this folder is [architecture §4.2](../../../docs/architecture.md#42-inside-a-module): rules in `domain/` without a framework, Zod schemas in `schemas/`, NestJS in `api/`, Temporal in `workflows/`, agent tasks in `agents/` (importing `@whytide/ai`, never `@mastra/*`), Next.js in `ui/`, every screen string a key in `messages/en.json`, the registries in `permissions.ts`, `prices.ts`, `events.ts` and `settings.ts`, the tests in `tests/`.
3. Commands, from the repository root: `pnpm -F enrichment build`, `pnpm -F enrichment typecheck`, `pnpm -F enrichment test`, `pnpm -F enrichment test:tenancy`, `pnpm -F enrichment lint`; the runs end to end are the worker's `core/apps/worker/tests/enrichment-run.test.ts`, and a changed workflow records a new history (`pnpm -F worker history:record`).
4. Stay inside this folder and the module's schema file. A change to a shared package is its own task.
5. No value in a workflow's input, an activity's result, an event, `sources_tried` or a log line: ids, source names, field names and codes only. The facts go from the source's activity straight to contacts.
6. A source gets the minimum input (RB-7.3.1): a company source the company's page, domain, name and country, never the person's data, and the run's ids, which never go to a vendor; it opens its own runs of the workspace with `context.tenant`, never around a vendor's call. A new source is a `defineSource` in `domain/sources/`, imported by its `index.ts`, and a name in a list; a skip in its own word is an `outcome` (README "Sources"). The workflow never orders sources itself.
7. A new source's name also goes in deploy:check's table, `SOURCE_NAMES` in `deploy/scripts/constants.ts`, under its list: `tests/deploy-table.test.ts` fails until it does.
8. No email address in an event, a workflow input, an activity's result, `providers_tried` or a log line: a lookup's candidates go through its `raw/` files, and only `addressOf` answers an address (README "Email lookups").
9. A phone is a contact point of kind `phone`, never an address: a reader of an address names `EMAIL_KINDS`, and no phone is in a log line, a span, an event or a workflow history (README "A person's phone").
