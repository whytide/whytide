# qualification.assess-fit

The assessment agent (alpha-p6-020): one anonymized person against the lead's audience, an ICP of the workspace (gamma-p5-050), a verdict per criterion with its evidence, the disqualifiers it sees and one sentence. [docs/concepts.md](../../docs/concepts.md) says how the answer is used, [docs/security.md](../../docs/security.md) what the model may see.

- **Task:** `task.ts`: `kind: classification`, no tools, prompt version 2 (title-check-ai), a budget of 12,000 input tokens, 1,500 output tokens and 1 credit. The model is `AI_MODEL_QUALIFICATION_ASSESS_FIT`, else the LLM port's first. The task file imports none of the module's registries (index, events, ids, errors), and the module never imports it: hosts load it from the sources (core/packages/ai README "Declaring a task"), and `assessPerson` takes it from the agent registry.
- **Prompt:** `prompt.v2.md`, the system prompt since title-check-ai: v1's, with the rules of `title_function` (a title of several roles, or shortened, the headline helping: `met` when one role does the work of one of the ICP's titles, `partially_met` for an adjacent function; the level word is seniority's) and the five people-type disqualifiers (`agency_or_consultant`, `freelancer`, `recruiter`, `student_or_intern`, `job_seeker`), which apply only when the ICP does not target that kind of person. `prompt.v1.md` stays, for the snapshots it made. The data blocks, in order: `<profile>` (headline, title, country), `<company>` (name, industry, size), `<evidence>` (up to five excerpts of the person's own words, which the batch reads from signals' reader for a lead signals found, gamma-p5-050; `[]` for an imported person), `<icp>` (titles, seniorities, industries, company sizes, countries), `<must_haves>` and `<disqualifiers>` (the seller's texts). A changed prompt is a new file, `prompt.v3.md` with `promptVersion: 3`, and runs the evals.
- **Schemas:** `schemas/assess-fit.ts`. The input, one field per block, is what `assessPerson` builds; a key the schema does not declare is dropped before a block is written. The output: `verdicts`, each `{ criterion, verdict, evidence }`, the criteria `title_function`, `seniority`, `company_size`, `industry`, `location` and `must_haves`, the verdicts `met`, `partially_met`, `not_met` and `unknown`; `disqualifiers`, codes of the closed list of eleven (F04 §4.2); `summary`, one sentence. A value off a list fails the schema.
- **Gate:** `criteria` (`domain/assess/checks.ts`): each criterion exactly once. A failed schema or gate is retried once, the failure in `<validation_error>`, then the call is `ai_failed`.
- **Evals:** `core/packages/ai/evals/qualification.assess-fit/`, thirty-seven synthetic profiles on four ICPs, five of them injections in the criteria and the evidence, five anonymization checks and seven title-check-ai's (a combined title, a shortened one, a combined one with one fitting role and one with none; an agency owner an ICP targets, an agency it does not, a student): `pnpm -F ai eval qualification.assess-fit`. Each case expects what a good model answers, so the same cases run live (`EVAL_LIVE=1`, by hand, every verdict expected) after a prompt change; on the fake, three cases answer invalidly first, to test the retry, and four fail twice, to end `ai_failed`.
