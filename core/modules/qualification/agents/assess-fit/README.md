# qualification.assess-fit

The assessment agent (alpha-p6-020): one anonymized person against the workspace's ICP, a verdict per criterion with its evidence, the disqualifiers it sees and one sentence. [docs/concepts.md](../../docs/concepts.md) says how the answer is used, [docs/security.md](../../docs/security.md) what the model may see.

- **Task:** `task.ts`: `kind: classification`, no tools, prompt version 1, a budget of 12,000 input tokens, 1,500 output tokens and 1 credit. The model is `AI_MODEL_QUALIFICATION_ASSESS_FIT`, else the LLM port's first. The task file imports none of the module's registries (index, events, ids, errors), and the module never imports it: hosts load it from the sources (core/packages/ai README "Declaring a task"), and `assessPerson` takes it from the agent registry.
- **Prompt:** `prompt.v1.md`, the system prompt. The data blocks, in order: `<profile>` (headline, title, country), `<company>` (name, industry, size), `<evidence>` (up to five excerpts; `[]` for an imported person), `<icp>` (titles, seniorities, industries, company sizes, countries), `<must_haves>` and `<disqualifiers>` (the seller's texts). A changed prompt is a new file, `prompt.v2.md` with `promptVersion: 2`, and runs the evals.
- **Schemas:** `schemas/assess-fit.ts`. The input, one field per block, is what `assessPerson` builds; a key the schema does not declare is dropped before a block is written. The output: `verdicts`, each `{ criterion, verdict, evidence }`, the criteria `title_function`, `seniority`, `company_size`, `industry`, `location` and `must_haves`, the verdicts `met`, `partially_met`, `not_met` and `unknown`; `disqualifiers`, codes of the closed list of eleven (F04 §4.2); `summary`, one sentence. A value off a list fails the schema.
- **Gate:** `criteria` (`domain/assess/checks.ts`): each criterion exactly once. A failed schema or gate is retried once, the failure in `<validation_error>`, then the call is `ai_failed`.
- **Evals:** `core/packages/ai/evals/qualification.assess-fit/`, thirty synthetic profiles on two ICPs, five of them injections in the criteria and the evidence and five anonymization checks: `pnpm -F ai eval qualification.assess-fit`. Each case expects what a good model answers, so the same cases run live (`EVAL_LIVE=1`, by hand, every verdict expected) after a prompt change; on the fake, three cases answer invalidly first, to test the retry, and four fail twice, to end `ai_failed`.
