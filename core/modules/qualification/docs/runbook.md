# qualification: runbook

- **Settings**: `AI_MODEL_QUALIFICATION_ASSESS_FIT`, the assessment agent's model, empty for the LLM port's first; `QUALIFICATION_BATCH_SIZE` and `QUALIFICATION_SCHEDULE_MINUTES`, read at the worker's start ([README](../README.md#settings)).
- **Failure modes**: the hard filters throw nothing. A person filtered by surprise: the reason and `detail` say what was compared, [concepts.md](concepts.md) and the fixtures how. A change to the rule changes the fixtures in the same merge request.
- **The assessment**: `ai_failed` comes back with its decision record, whose `gates` holds each failed attempt's reason (`invalid`, `gates`) and issues: read it in the database, never in a log. `icp_version_stale` means the ICP changed during the batch: assess again with the new version. `assessment_agent_not_loaded` means the host started without `loadAgentTasks()`. A model or port error (`llm_*`) is thrown for the activity's retry.
- **A prompt change**: a new `prompt.v<N>.md` and `promptVersion`, then `pnpm -F ai eval qualification.assess-fit`, on the fake and, by hand, live (`EVAL_LIVE=1`: every verdict expected; commit its record from the eval's `runs/` with the change).
- **The score**: a surprising fit: the snapshot's verdict rows hold each criterion's `weight` and `points`, which give the fit before the must cap ([concepts.md](concepts.md) "The score"). `icp_version_stale` from `scoreSnapshot` means the ICP moved since the assessment: assess again. `score_snapshot_not_found` means no snapshot of the workspace has that id. A changed formula is a new scorer version with its own golden file, never an edit of `fit-v1`.
- **The re-score**: after a criteria save, `pnpm rescore --workspace <id or slug>` (every scored lead) or `--person <id>` prints `rescore_requested: <requestId>`; the worker's run `qualification.rescore:<workspaceId>:<requestId>` answers `{ rescored, skipped }`. The route's `marked` is 0 when no lead has a snapshot to move: none scored at the current ICP version (the batch assesses them), or all scored with these criteria. A lead skipped has no scored snapshot at the current ICP version: the batch assesses it. The panel's "still running" after thirty seconds means the run has not reached the lead: look for the run in Temporal's UI. A failed page fails the run; asking again re-scores what is left, and a lead scored with these criteria is skipped.
- **The batch**: in Temporal's UI, `qualification.batch:<workspaceId>:current` is the workspace's batch (its last run) and `qualification.batch_tick` the schedule; a batch's result counts the leads selected, filtered, scored and failed, and names why it stopped. A tick skips a workspace whose ICP has no targeting or whose leads are all decided at its version; a tick that failed names the first failed workspace's code, and the others were started. Stuck leads: `pending` with `status_reason` `insufficient_credits` waits for credits, then the next tick; `pending` with `provider_failed` is tried again by the next batch, three attempts per ICP version (`assessment_attempts`); `ai_failed` with `provider_failed` failed the third and is assessed again only at the next ICP version (a targeting change), as is any `ai_failed` lead. A batch that fails at the same lead every tick holds a reservation for it (`credit_usage`, its key `qual:<personId>:…`): its failure code says why (`assessment_agent_not_loaded`: the worker started without its agents); after the 24-hour lease the batch releases it and reserves again under the next attempt's key.
- **The golden set**: `pnpm export:golden --workspace <id or slug> [--week 2026-W43]` prints `golden_set_written: w/<workspaceId>/exports/golden-set-<date>.jsonl, <n> lines`; the file stays 7 days at most, and the route answers the same. A line `input_from: "rebuilt"` reads the person and the ICP as they are now, since a raw prompt is never read past its `raw_purge_after` (`AI_RAW_RETENTION_DAYS`), whether `pnpm -F ai purge-raw` ran or not: export a week before its prompts go. `files_too_large`: the set passed 25 MiB, export it by week. `contacts_input_invalid`: a week the year does not have.
