# qualification: the brief for a coding agent

1. Read `README.md`, then `docs/concepts.md`, `docs/data.md`, `docs/flows.md`, `docs/security.md` and `docs/runbook.md`. They say what is true now and change in the same merge request as the behavior.
2. The rules: [coding](../../../docs/rules/coding.md), [security](../../../docs/rules/security.md), [delivery](../../../docs/rules/delivery.md). The shape of this folder is [architecture §4.2](../../../docs/architecture.md#42-inside-a-module): rules in `domain/` without a framework, Zod schemas in `schemas/`, NestJS in `api/`, Temporal in `workflows/`, agent tasks in `agents/` (importing `@whytide/ai`, never `@mastra/*`), Next.js in `ui/`, every screen string a key in `messages/en.json`, the registries in `permissions.ts`, `prices.ts`, `events.ts` and `settings.ts`, the tests in `tests/`.
3. Commands, from the repository root: `pnpm -F qualification build`, `pnpm -F qualification typecheck`, `pnpm -F qualification test`, `pnpm -F qualification lint`.
4. Stay inside this folder and the module's schema file. A change to a shared package is its own task.
5. The hard filters stay pure and import nothing outside `domain/hard-filters/` (a test reads the imports). A change to the title rule or the size parser changes `tests/fixtures/titles.json` or `sizes.json` and `docs/concepts.md` with it.
6. The assessment agent's task file (`agents/assess-fit/task.ts`) imports none of the module's registries (`index.ts`, `events.ts`, `ids.ts`, `errors.ts`), and nothing in the module imports it: hosts load it from the sources. The anonymizer stays an allow-list; a change to it changes `tests/anonymize.test.ts` and `docs/security.md` with it.
7. The scorer is versioned (`SCORER_VERSION`, `fit-v1`): a change to `computeFit`, `decide` or their numbers is a new version with its own golden file under `tests/fixtures/golden/`; `fit-v1.json` is never edited. A new why key gets its message in `messages/en.json`, its `t()` in `ui/labels.ts` and its params in `docs/data.md`.
8. Tests import the files they test, never the module's `index.ts`: it exports the NestJS `api`, whose decorators Node cannot run from the sources.
9. After a change to `workflows/workflows.ts`, `pnpm -F worker test:replay` must still replay `workflows/__histories__/`; a new path records a history of its own with `pnpm -F worker history:record` (core/apps/worker/README.md). A new table gets its isolation test in `tests/tenancy.test.ts` and its rows in `erasePerson`.
10. The panel (`ui/rescore-action/`) uses the kit's states and words every string through `messages/en.json`; its Playwright specs are the web host's (`core/apps/web/tests/qualification-states.spec.ts`, `rescore-action.spec.ts`), each in an e2e workspace of its own.
