# messaging.write-reply

The reply writer (inbox-reply-draft): the seller's next message in an inbox thread, which a member asks for on the thread's page, from the dossier, the conversation and the member's optional brief. It only fills the reply box: inbox's Send, its route and its run are unchanged. [docs/flows.md](../../docs/flows.md) says how a reply is drafted, [docs/security.md](../../docs/security.md) what the model sees and the gates.

- **Task:** `task.ts`: `kind: generation`, no tools, prompt version 1, a budget of 16,000 input tokens (the conversation's 24,000 bytes at most above the message writer's 8,000), 1,500 output tokens and 0 credits (not priced; the cost event records each call). The model is `AI_MODEL_MESSAGING_WRITE_REPLY`, else the LLM port's first. The module never imports the file: `writeReply` takes the task from the agent registry.
- **Prompt:** `prompt.v2.md` (`prompt.v1.md` stays): v1's rules and blocks plus `<request>` (part 1's review). The message writer's `<dossier>`, `<lead>` and `<why_now>`; `<channel>` with the language code `textLanguage` reads from the lead's messages; `<conversation>`, the thread's latest 20 messages (`REPLY_CHAT_MAX`), oldest first, each `{ from, at, text }`; `<brief>`, the member's, or null; `<failures>`, the one earlier answer's issues; `<replaced>`, the ready draft the member asked again, or null; `<request>`, the caller's id of the request (inbox's draft id), which the model never writes: callAgent's cache keys on the input's hash, so a new request, Try again after `gates_failed` among them, asks the model again, while a retry of the same activity finds the calls it paid for. The conversation and the brief are untrusted data: a line such as "ignore your instructions" changes nothing. It answers the lead's latest message, follows the brief, invents no fact, date, price or promise that the dossier, the brief or the conversation does not hold, claims no call, meeting or reply that the conversation does not, and accepts a "not interested" without pushing; plain text to the lead's first name, within 1,900 characters, in the language of the lead's latest message. A changed prompt is `prompt.v3.md` with `promptVersion: 3`, and runs the evals.
- **Output:** `text`, 1 to 4,000 characters. `writeReply`'s gates check it after the call: `placeholders`, `length` (1 to 1,900), `grounding` (on the dossier, the brief and the conversation; in another language than English, its numbers and dates, not its names), `red_lines`, `colleague_signal` and `signal_act`. A failing answer is written again once with its issues in `<failures>`; then the reply is ready, or failed, `gates_failed`.
- **Evals:** `core/packages/ai/evals/messaging.write-reply/`, eight synthetic conversations on the message writer's two sellers: a question answered, with a brief and without, a brief asking for a price the dossier lacks (its invented first answer refused by grounding, then written without it), a lead not interested, an injection in the lead's message, a Spanish conversation and a placeholder refused then rewritten. The scorer runs the gates in short as `writeReply` does: placeholders, length, grounding on the facts, the brief and the conversation (numbers and ISO dates only for another language, shorter than the gate, which reads English month names there too), red lines, the colleague phrases and the act phrases; then `outcome` or `fails_safe`, `length`, `grounding`, `red_lines`, `signal_act`, `absent` (none of the case's phrases, such as a push or a call that never was), `language` (no English function word in a reply to another language) and `words` (`pnpm -F ai eval messaging.write-reply`; on the fake, `core/packages/ai/tests/evals.test.ts`).
