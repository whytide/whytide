# messaging.write-message

The writer (alpha-p9-020), the second of the two calls (F09 §5.1): the text of one LinkedIn message, a lead's first or a sequence step's (beta-p3-010), from the dossier and the plan. [docs/flows.md](../../docs/flows.md) says how a draft is made, [docs/security.md](../../docs/security.md) what the model sees and the gates.

- **Task:** `task.ts`: `kind: generation`, no tools, prompt version 2, a budget of 8,000 input tokens, 1,500 output tokens and 0 credits (not priced in alpha). The model is `AI_MODEL_MESSAGING_WRITE_MESSAGE`, else the LLM port's first. The module never imports the file: `writeDraft` takes the task from the agent registry.
- **Prompt:** `prompt.v2.md` (beta-p3-010; `prompt.v1.md` stays for the drafts written on it). The planner's blocks, `<step>` among them, plus `<plan>`, before `<failures>` and `<replaced>`. `<step>`, empty for a lead's draft, is a sequence step's kind and the same person's earlier approved texts, untrusted and no facts: `first_message` writes as the first message after an accepted invitation, never as if there had been a conversation, a call or a reply; `follow_up` builds on the earlier texts without repeating, quoting or pointing back at them, and never claims the lead answered. Once drafts have run on it, a changed prompt is `prompt.v3.md` with `promptVersion: 3`, and runs the evals.
- **Output:** `text`, 1 to 4,000 characters. The module's gates check it after the call: `placeholders`, `length`, `grounding`, `red_lines`, `colleague_signal` (`domain/gates/`; beta-p3-020). Prompt version 2's `<failures>` does not describe `colleague_signal`; its issue names the words that hit.
- **Evals:** `core/packages/ai/evals/messaging.write-message/`, thirty synthetic dossiers on two sellers: alpha's twenty, a lead's message each, and ten sequence steps with `<step>` (beta-p7-040: three `first_message`, four `follow_up`, three for the colleague gate). The scorer runs the gates in short after every answer, `colleague_signal`'s phrases after `red_lines`, then checks the text's length against `<channel>`, no red-line phrase, its grounding (every name and number in a fact, 0.9), the words the case expects, that four injections in the evidence and a case whose two answers name colleagues fail safe, and in the step cases `colleague_signal` (no colleague phrase and none of the case's `colleagues`), `no_repeat` (no run of 8 words of an earlier text) and `absent` (no reply the person never sent) (`pnpm -F ai eval messaging`). Its copies of `RED_LINES` and `COLLEAGUE_SIGNAL_PHRASES` equal `domain/gates/format.ts` and `constants.ts`: `core/packages/ai/tests/evals.test.ts` fails when a phrase changes on one side only.
