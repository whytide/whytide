# messaging: runbook

Settings: `LINKEDIN_NOTE_LIMIT`, `AI_MODEL_MESSAGING_PLAN_MESSAGE`, `AI_MODEL_MESSAGING_WRITE_MESSAGE` (README.md "Settings"); a model must be priced in `COST_PRICES_JSON`, or the worker refuses to start (`cost_price_missing`). The route logs the api's request line only; a failure is a code:
- `dossier_lead_not_found` (404): the workspace has no lead for the person; check contacts' lead.
- `writer_agent_not_loaded` (500): the process started without `loadAgentTasks()`, which the worker runs at its start.
- `draft_not_found` (404), `draft_not_editable` (409: the draft is being written, ask again once it is not `drafting`; or, for `approveStepDraft`, it was approved already), `messaging_input_invalid` (400: an edit above the channel's limit; for `requestStepDraft`, a step key outside `STEP_KINDS` or more than three earlier ids).
- `draft_text_refused` (400): an edit or an approval whose text breaks a gate; `details.issues` names each (a placeholder, a red-line phrase, a colleague's signal, the length). Change the text; never loosen the gate.
- `draft_not_ready` (409): `approveStepDraft` on a draft still `drafting`; approve it once the writer is done, or the sweep has failed it.
- `draft_step_mismatch` (409): `approveStepDraft` with a lead's draft, or with another step execution's id than the draft's: the caller passed a wrong id.
- `step_draft_not_editable` (409): `PATCH` or regenerate on a sequence step's draft; it changes in "Up next" only (approvals' path).
- `internal_error` (500) with a `ZodError` in the log: the assembly built a dossier its schema refuses, a bug in `domain/dossier/assemble.ts`; never loosen the schema to pass it.

A draft's `flag_reasons` says why it is not `ready`: a gate's issues (`flagged`: edit or regenerate it), or `{ code }` (`failed`): `ai_failed` (the model's answer failed its schema twice; its decision record, `decision_record_id`, holds why), `draft_requester_not_member` (the member left the workspace), `dossier_lead_not_found` (the lead was deleted), `write_failed` (the writer failed past its three attempts: the workflow `messaging.draft:<workspace>:<draft>` in Temporal shows the activity's error code). A draft `drafting` for long has no run: check that the worker runs and that its outbox delivered `messaging.draft_requested`; the draft panel shows it as being written, asks for it less often as it ages and, past twenty minutes, stops with a note and Check again, which reads it once. The panel's error state names the code of a read the api refused; its retry reads the page again.

A sequence step's draft (beta-p3-010) also fails with `earlier_draft_invalid` (an earlier draft id is not an `approved` step's draft of the same person: campaigns passed a wrong id, or the earlier draft is no longer approved) or `draft_stuck`. A stuck draft: the hourly sweep (`messaging_sweep`, schedule `messaging.sweep`) fails every draft still `drafting` 30 minutes after it was made, with no text, and a step's draft then publishes `messaging.step_draft_ready`, so "Up next" shows it to write by hand. A run that answers later is dropped, never written over `failed`. Many swept drafts mean the writer's runs do not end: check the worker, the outbox's delivery of `messaging.draft_requested` and the provider's rate limits; the run's history in Temporal names the activity's code. A paused schedule (`WORKER_SCHEDULES=off`) sweeps nothing: drafts stay `drafting` until it runs.
