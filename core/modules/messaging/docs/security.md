# messaging: security

- **Personal data:** the dossier holds a lead's first name, headline, title and location, the employer, and the person's own comment on a post with the post's URL ([data.md](data.md)), from stored business fields only. Its strict schema refuses any other field, so no last name, contact detail, photo or anything a visibility setting hides can enter it (`tests/schema.test.ts`). It is built per request and stored nowhere.
- **Who:** `drafts.read` for the dossier and the drafts, `drafts.write` to ask for, edit or regenerate a draft: every role of the workspace. A person of another workspace, or one without a lead, is `dossier_lead_not_found`, and another workspace's draft `draft_not_found`, the answers for none, so the routes tell nothing about other workspaces. The worker writes a draft for the member who asked, after checking that they are a member still, never as a service.
- **Stored:** a draft's text, a member's edit and the gates' issues, which may quote a text's words, are `business_contact` ([data.md](data.md)); `erasePerson` deletes a person's drafts. No text, fact or name is in a log line, a span or an error: an error names a code and, for an input, its fields. The one exception is `draft_text_refused` (beta-p3-020). Its `details.issues` are the gates' issues, which may quote the member's own words, answered to that member as a 4xx, which the api never logs. A caller that logs it logs the code only: the logger keeps an AppError's details, and `phrase` is no redacted key.
- **How data leaves:** the routes' answers, to the workspace's members; the writer's blocks, to the LLM port; the grounding sample's sheet, a week's drafts as written with their dossier's facts, under the workspace's `exports/` for 7 days (`@whytide/ai`'s docs/security.md). The draft panel shows a member the drafts, each with its model id and prompt version, and the facts a plan cites, each source in words from its table and column, never the reference with its record ids; Copy puts a text on the member's clipboard, and nothing is sent from the product.
- **The AI:** the two agents read the dossier's values with their fact ids only, never a source, a link, a record id, the hash or a last name; the prompt's header names the blocks, then the data sentence, then marks `<lead>` (the lead's profile and their company's) and `<why_now>` (the newest three events' reactions, excerpts and comments) untrusted: the lead, their company's page and the authors of posts wrote them. An answer is validated against its schema (unknown keys dropped, the angles and calls to action closed lists), then by the gates in code: the plan cites only facts it read; the text keeps no placeholder, keeps to the channel's length, names no name, company, tool, number or date that no fact holds, and says no red-line phrase. A failing text is regenerated or flagged, never `ready`; nothing is sent from here.
- **The gates:** `domain/gates/`, cases in `tests/gates.test.ts`; README.md "Decided here" says what grounding misses.
- **A sequence step's draft** (beta-p3-010): a follow-up's `<step>` holds only the same person's `approved` step drafts in the workspace, read by id inside the activity; another person's, another workspace's or an unapproved draft fails the draft `earlier_draft_invalid` before any model call (`tests/safety/step-draft-failure.test.ts`). The ids travel in the event and the workflow's input, never a text. `<step>` is marked untrusted in both prompts' third line, as the seller may have edited its texts, and its texts are no facts: the gates ground the text on the dossier alone. A failed or stuck draft keeps no text, so approvals has nothing of it to send; a `connect` note is empty and calls no model. alpha's routes never change a step's draft (`step_draft_not_editable`) and its list never shows one.
- **The two layers of colleague privacy** (beta-p3-020): the dossier holds the person's own signals only (signals' `listEvidence(personId)`), so the model never reads a colleague's event; the `colleague_signal` gate catches what the model or the owner writes anyway, on the writer's every answer (`flagged`, never `ready`), on an edit (`PATCH`, 400 `draft_text_refused`) and on an approval (`approveStepDraft`), in English only. The grounding gate also flags, in the writer, any name no fact holds. contacts' `colleaguesOf` answers names only, no id or URL, read in the run that checks; an issue quotes the text's own words, never a stored name (`tests/safety/colleague-signal.test.ts`).
- **The freeze:** an approved step's draft is approved once, under a condition on its status, and nothing writes it again; `approvedContent` answers its text and the SHA-256 the send compares, so a text changed after the owner's approval is never sent as approved.
