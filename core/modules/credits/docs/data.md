# credits: data

Eight tables in `core/packages/db/prisma/schema/credits.prisma`, six created by the migration `20261022103000_credits_initial`, `credit_alerts` by `20261113025150_credits_alerts` and `credit_alert_mails` by `20261113051853_credits_alert_mails`. Every id is `<prefix>_<ULID>` (`ids.ts`; the functions make theirs with `credits_new_id`); every instant is a `timestamptz`; every amount is `numeric`.

| Table | Id | Columns | Keys | Scope | Written by |
|---|---|---|---|---|---|
| `plans` | `plan_` | `code`, `name`, `monthly_allowance`, `is_fixed`, `created_at` | `code` unique | global | `billing_writer` |
| `subscriptions` | `sub_` | `organization_id`, `plan_id`, `status`, `period_start`, `period_end`, `created_at` | `organization_id` unique | organization | `billing_writer`, `credits_seed_self_hosted` |
| `credit_grants` | `grant_` | `organization_id`, `subscription_id`, `amount`, `reason`, `period_start`, `period_end`, `created_at` | `(organization_id, reason, period_start)` unique | organization | `billing_writer`, `credits_seed_self_hosted` |
| `credit_usage` | `usage_` | `organization_id`, `workspace_id`, `action`, `quantity`, `credits`, `status`, `idempotency_key`, `lease_expires_at`, `subject_ref`, `created_at`, `settled_at`, `price_list_version` | `(workspace_id, organization_id, idempotency_key)` unique; index `(workspace_id, created_at)` | tenant | `app` |
| `credit_balances` | `bal_` | `organization_id`, `granted`, `reserved`, `committed`, `updated_at` | `organization_id` unique | organization | the triggers |
| `price_list` | `pl_` | `action`, `credits`, `unit`, `version`, `effective_from`, `announced_at`, `withdrawn_at` | `(action, version)` unique | global | `billing_writer` |
| `credit_alerts` | `calert_` | `organization_id`, `period_start`, `threshold`, `used`, `granted`, `notified_at`, `tries`, `created_at` | `(organization_id, period_start, threshold)` unique | organization | `app` (the worker's check and mail) |
| `credit_alert_mails` | none | `alert_id`, `user_id`, `mailed_at` | `(alert_id, user_id)` primary | organization, through its alert | `app` (the worker's mail) |

`status` is the enum `subscription_status` (`active`, `cancelled`) on `subscriptions` and `credit_usage_status` (`reserved`, `committed`, `released`, `expired`) on `credit_usage`. Foreign keys: `subscriptions.plan_id` and `credit_grants.subscription_id`; `organization_id` has none, `organizations` being tenancy's table.

The migration `20261022160000_credits_reserve` adds non-negative CHECKs on `credit_usage` (`credits`, `quantity`), `plans.monthly_allowance` and `credit_grants.amount`, the index `(organization_id, status, lease_expires_at)` for the lease sweep, `app`'s column grant and the trigger `credit_usage_settle_once` ([docs/security.md](security.md)), and makes `credits_seed_self_hosted` skip a subscription that is not active.

The migration `20261105085249_credits_price_notice` (gamma-p2-060) adds three columns. `price_list.announced_at` is when the start that wrote a pending rise announced it, null for a version in effect at once and for the versions written before. `price_list.withdrawn_at` is when a pending version was withdrawn, null otherwise; the CHECK `price_list_withdrawn_before_effect` keeps it null or earlier than `effective_from`, so a version in effect is never withdrawn, and `billing_writer`'s UPDATE on `price_list` narrows to this one column, so no price of any version changes once written. `credit_usage.price_list_version` is the version the reserve charged; the migration fills it for the rows written before from the version in effect at each row's `created_at`, where that version prices the row's action, and leaves it null otherwise. `app`'s column grant leaves it out, so a row's version never changes after the reserve ([docs/security.md](security.md)).

The SQL written by hand in the migrations: the grants ([docs/security.md](security.md)); the triggers `credit_grants_balance` and `credit_usage_balance`, which take off what a row counted before a change and add what it counts after; and `credits_seed_self_hosted(organization_id)` (README "Periods").

The migration `20261113025150_credits_alerts` (gamma-p7-020) creates `credit_alerts`, one row per organization, period and threshold, the "once per threshold per period" key (README "Alerts"): `period_start` is the subscription's at the crossing; `threshold` 80, 95 or 100 (CHECK `credit_alerts_threshold`); `used` and `granted` the period's figures at the crossing, carry-over aside; `notified_at` null until the Owners' mail went, this row's or a higher threshold's of the same check; `tries` the mail's rounds that failed their attempts, 0 or more (CHECK `credit_alerts_tries_non_negative`). `app` reads and inserts it and updates `notified_at` and `tries` only; nobody deletes a row; `billing_writer` does not see it ([docs/security.md](security.md)). No `person_id`, so no eraser; no `workspace_id`, so no tenancy test.

The migration `20261115121624_credits_alert_thresholds` (env-settings-b) widens the CHECK `credit_alerts_threshold` to any whole percent from 1 to 100, the thresholds `CREDITS_ALERT_THRESHOLDS` names (README "Settings"); the rows written before, 80, 95 and 100, pass it as they are.

The migration `20261113051853_credits_alert_mails` (review-gaps-2) creates `credit_alert_mails`, one row per alert and recipient mailed, written right after that recipient's send (README "Alerts"): `alert_id` references `credit_alerts` (RESTRICT on delete and update); `user_id` is tenancy's user, a plain id, the Owner or Admin mailed; `mailed_at` when the row was written. The primary key `(alert_id, user_id)` keeps one row per recipient. `app` reads and inserts it only: its UPDATE and DELETE are revoked in the migration's hand-written SQL, so a recorded recipient stays recorded; `billing_writer` does not see it ([docs/security.md](security.md)). No address or name, so no eraser; no `workspace_id`, so no tenancy test.

Personal data: none. `subject_ref` holds an id, never a person's data. Nothing is deleted in alpha: grants and usage rows are the ledger.
