# linkedin: flows

- **POST /accounts/connect**: after the host's guards (session, workspace, `linkedin.connect`, origin), on a `whytide:own-runs` route: the acknowledgment, the zone; a run that refuses a connected account; the provider's `createHostedAuthLink` with the return URLs, 30 minutes, outside any run; a run that upserts the user's row as `pending` with the link's `providerRef`. The browser goes to the link.
- **The provider's page**: the user signs in at the provider, which sends the browser back to the screen and posts `account.connected` to the webhook route. On the fake, the link is the test-mode route `connectOnVisit` (served under `APP_ENV=test` only, on the web's origin through its `/api/linkedin/*` rewrite), which posts the webhook before it redirects.
- **POST /v1/linkedin/webhooks/{provider}**: the host's limit per address, the raw body read, then `handleWebhook`: the adapter's `parseWebhook` checks the signature (401 otherwise). `account.connected`: the pending rows by `providerRef`, across workspaces, on the module's client; for each, the workspace's organization, the reference sealed, then one run in that workspace: `connected`, the sealed reference, its hash, `linkedin.sender_account_connected` when it was not connected. Other kinds: the rows by hash, one run each, the status, the event when it crosses into `disconnected`.
- **GET, PATCH, DELETE /accounts…**: in the request's tenant run; another workspace's account is not found (404). DELETE writes the event in the same transaction.
- **POST /accounts/{id}/refresh**: after the host's guards and `@Idempotent()`, in the request's tenant run: the account (another workspace's is 404), then `linkedin.status_refresh_requested` written to the outbox in the same transaction; 202 with the account. In the worker, the event's delivery runs in that workspace's tenant run; the subscriber (`events.ts`) takes the workspace from it, `currentTenant()`, and starts `linkedin_refresh_account` with `startWorkflow`, by the event's id, so a second delivery starts none. The screen asks for the account every two seconds until its status changes, thirty seconds at most.
- **linkedin_status_refresh** (worker, hourly): `linkedin_list_workspaces`, global, the workspaces' ids from tenancy's `listWorkspaceIds()`, outside any run; for each workspace, `linkedin_list_referenced_accounts` in that workspace's run, its accounts with a reference, ids only; then `linkedin_refresh_status` for each account in turn.
- **linkedin_refresh_status** (worker): the row and its reference in the activity's run; `withDecryptedRef` opens it; `getAccountStatus` outside any run; then a run that stores the status and writes the event on a crossing, and one that logs the `status_check`.
- **reserveReads** (the caller's run): the account; refused, and logged, when it is not `connected` or its window is closed; then the day's usage row, inserted if missing (`ON CONFLICT DO NOTHING`) and locked (`SELECT … FOR UPDATE`), so concurrent reservations of the account wait here; the day's reservations past their hour expire; the cap checked against reserved plus committed plus `count`; the reservation, the day's `reads_reserved` and the log row, or the refusal's log row. The run's commit releases the lock.
- **linkedin_read_post_engagers** (worker): `withDecryptedRef` opens the reference; `listPostEngagers` outside any run; a run that logs `read_engagers` with the outcome; the page to the files port at the given `raw/` key; the key, the count and the next cursor back. The caller's run holds the read's reservation.
- **linkedin_read_profile** (worker): the request file at the given `raw/` key read; `withDecryptedRef` opens the reference; `getProfile` outside any run; a run that logs `read_profile` with the outcome and no object; the profile to the files port at the given `raw/` key; the key back. The caller's run holds the read's reservation.
- **commitReads, releaseReads** (the caller's run): the reservation's day row locked first, the reservation read again, then its status and the day's counters; a settled one answers as before.
- **GET /accounts/{id}/usage**: in the request's run, the account, its quota day and window from the clock, the day's row if any.
