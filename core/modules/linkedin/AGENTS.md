# linkedin: the brief for a coding agent

1. Read `README.md`, then `docs/concepts.md`, `docs/data.md`, `docs/flows.md`, `docs/security.md` and `docs/runbook.md`. They say what is true now and change in the same merge request as the behavior.
2. The rules: [coding](../../../docs/rules/coding.md), [security](../../../docs/rules/security.md), [delivery](../../../docs/rules/delivery.md). The shape of this folder is [architecture §4.2](../../../docs/architecture.md#42-inside-a-module); the screen follows [core/apps/web/docs/screens.md](../../apps/web/docs/screens.md): `.tsx` files only under `ui/`, the API client from `@whytide/web/api/*`, which this package does not list.
3. Commands, from the repository root: `pnpm -F @whytide/linkedin build`, `typecheck`, `test`, `test:tenancy`, `lint`; then `pnpm -F api test` for the routes and the webhook, `pnpm -F worker test` and `test:replay` for the workflows and the subscriber, and `pnpm -F web test` for the screen, which load this module's `dist/`.
4. The reference is opened in `workflows/` only (`withDecryptedRef`), never in `api/`, `domain/` or the index: the lint's `decrypt-in-worker-only` refuses it. Never log, return or publish it, sealed or not.
5. No provider call inside a run: connect opens its own runs around it (`whytide:own-runs`), the webhook opens one only once the account is found.
6. Stay inside this folder and `linkedin.prisma`; a change to a shared package or a host is its own task, or called out as a host change.
7. No read of LinkedIn without a reservation: `reserveReads`, the read, then `commitReads` or `releaseReads`, and `logAction` for the read (README.md "Read quota"); the clock is `domain/clock.ts`, never `new Date()` in the quota.
8. The hard maximums are `domain/quota/constants.ts` and the CHECKs of `linkedin_send_quotas`, never a setting or a literal elsewhere: `pnpm -F @whytide/linkedin test:safety` fails on a second declaration. A day's draw takes `random()` from `domain/clock.ts`, never `Math.random()` in the quota.
9. The receiver's order is verify, filter, file, one transaction (`domain/receiver/`, docs/flows.md): nothing of a dropped event is stored or logged, the file is written before the run and never inside one, and the receipt, the outreach row's change and the event commit together; no provider or files call inside a run.
10. No send without a reservation: `reserveSend` under the step's key before the port call, then `commitSend` or `releaseSend` as `SEND_ERROR_MAP` says (README.md "Read quota"); the state refusals live in `sendStateRefusal` alone, and nothing is sent on Saturday or Sunday in the account's zone.
11. The operator's command, `cli/control.ts` (`pnpm linkedin:control`), changes the switches only through `domain/controls/`: no SQL of its own, so the routes, the screen and the command apply the same rules and write the same control events.
12. No send but through the send activities (`workflows/send.ts`): nothing else calls the port's `sendInvite`, `sendMessage` or `withdrawInvite`; other modules call the activities by name. A provider ref never leaves the outreach row: answers hold ids and codes.
13. Every health change goes through `applyHealth` (`domain/health/apply.ts`), in its cause's transaction, the account's row locked first: nothing else writes `health_state`, `health_changed_at` or `paused_until` (`testing/`'s `setHealth` is for tests), and a warning is never recorded without its pause.
14. The own-account routes check the account's owner in the domain (`domain/access.ts`: `ownAccount`, `seenAccount`, and the kill switches' principal), never a permission alone: a Member reaches their own account only, and a removed member's pause is its owner's to lift (gamma-p6-070).
