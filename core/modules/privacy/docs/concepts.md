# privacy: concepts

- **Erasure**: the deletion of everything a workspace holds about one person, on that person's request, in one tenant run: all of it commits, or nothing does. It is per workspace: the same person in another workspace keeps its rows.
- **Eraser**: a module's function that deletes the person's rows in its own tables, in the caller's run, and returns the rows it deleted by table. Each module erases its own rows; privacy only runs them.
- **Dependency order**: a module whose rows name another module's rows (a draft and a snapshot name their decision records) is erased first, so no erased row is left pointing at nothing and no row is read after its reference is gone. Contacts goes last, since every other row names the person.
- **Erased hash**: the salted hash of the person's normalized URL, of each provider id and of each email address they held, that contacts keeps with kind `erased`; for a person without a LinkedIn profile (gamma-rf-050), their addresses' only. An import or a signal run that meets it skips the person, and no command adds the person again. It is the only trace of the person left, and it is not reversible without the salt.
- **Erasure log**: one row per committed erasure: its reason, the URL's erased hash for a request (the first address's for a person without a LinkedIn profile), when it was asked and done, the counts by module and table, and the operator. It proves the erasure without naming the person.
- **The 30-day rule**: retention, not a request: every day, a person of the EU, the EEA, the UK or no known country whom no channel touched 30 days after being found is deleted through the erasers, with the reason `retention_never_contacted` and no hash kept. The clock is `persons.created_at`, which never resets.
- **Candidate**: a person the 30-day rule deletes at a run's cutoff (README.md "The 30-day rule"). **Guard**: the job's first look, after the lead's lock, that the candidate is still untouched. **Recheck**: the same check, and the rule again, on the person's row read under its own lock right before contacts deletes it, which waits for a touch still being written. A refusal of either rolls the person's run back.
- **Sweep**: the erasers run again for the persons a run deleted, 15 minutes later, for the rows a batch or a draft in flight wrote meanwhile.
- **Operator**: the person who runs the command, named with `--operator`; never the person erased.
- **Dry run**: the erasure with every step, rolled back at the end on purpose, to see the counts before the real one.
- **Lead deletion**: `pnpm lead:delete`, the erasure of a person no channel ever reached and no never-contact entry names, with the reason `lead_deleted` and no hash kept, so that the same person can be added again (README.md "Deleting a lead"). A contacted person is `person_contacted`, a suppressed one `person_suppressed`.
