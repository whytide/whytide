# inbox.classify-reply's evals

The reply classifier ([inbox's agent](../../../../modules/inbox/agents/classify-reply/README.md)) measured on 200 synthetic replies, and, by the owner, on the testers' labeled replies (gamma-p4-040, gamma-p7-065). The runner is the package's ([README "Evals"](../../README.md#evals)).

- **The cases** (`cases.json`): 200, every one invented: no real person, company, address or reply; the few addresses and links, which the mask must take out, are on reserved names (`example.com`, `.example`). Each name starts `syn-`, so a case reads as synthetic wherever it is printed. 26 `interested`, 24 `not_now`, 26 `not_interested`, 22 `out_of_office`, 42 `opt_out`, 22 `bounce`, 38 `other`; 25 of the opt-outs say it in words beta's phrase list does not match ("take me off your list", "leave me alone"), the model's part of the recall. Each `expected` is what a good model answers, so the cases run live as well.
- **The checks** (`score.ts`), each averaged over the cases that report it: `label` (the expected label, and a synthetic case's return date), `fails_safe`, `masked` (on the fake), and positive against the rest: `positive_recall` on the cases expecting `interested`, `positive_precision` on those the model called `interested`; `opt_out_recall` on the cases expecting `opt_out`, passing when beta's phrase list matches the reply or the model says `opt_out`, the system's order. The phrases are read when `score.ts` loads, as text, from inbox's `domain/opt-out/constants.ts` (the ai package never imports inbox), and fewer than 10 read stops the run. On the fake: `label` 0.9, `opt_out_recall`, `fails_safe` and `masked` 1, `positive_recall` and `positive_precision` 0.93. Live: `positive_recall` and `positive_precision` 0.93 each, which keeps the F1 at 0.93 or more, `opt_out_recall` 0.99, `label` 0.9, `fails_safe` 1.
- **The golden set** (`golden.ts`): `--cases <file>` adds a file of inbox's [reply golden set](../../../../modules/inbox/README.md#the-reply-golden-set) to these cases, live only. Each line becomes `golden-<line number>`, its input built from `earlier` and `text` as inbox's classifier builds it (the last 6 messages, each text cut to the model's bound), and `expected` the owner's `class_label`, or, on beta's lines with none, `{ positive }`, which reports only the two positive checks. A golden case's `label` compares the label alone.
- **Refused, exit 2, before any call:** `--cases` without `EVAL_LIVE=1` (the fake has no answer for a real reply), a file inside the repository, another task, and `EVAL_LIVE=1` in the pipeline.

## The owner's golden run

Live and billed, by hand, never in the pipeline:

1. Write the golden set with the operator's `pnpm inbox:export-labels` (`--workspace` for one), which holds every member's threads (the Owner-only route holds the caller's own). Copy the file it names, `w/<workspaceId>/exports/<file>`, from the files storage to a folder outside the repository. To cap the cost, cut it to fewer lines.
2. `EVAL_LIVE=1 pnpm -F ai eval inbox.classify-reply --cases <file>`, the file's absolute path, on `PROVIDER_LLM`'s model (its key in `.env.local`), at its price: the 200 synthetic cases, then the file's.
3. Delete the file. Format and commit the run's record, `runs/<date>.json`: the counts (`cases`, `golden`), each check's mean and threshold, and each case's name and scores, never a text, an input or a reply.
