# Contributing

Whytide is built one task at a time, by people and by coding agents under the same rules.

1. Read [AGENTS.md](AGENTS.md), then [docs/rules/delivery.md](docs/rules/delivery.md): how a task becomes a merge request, and what "done" means.
2. Follow [docs/rules/coding.md](docs/rules/coding.md) and [docs/rules/security.md](docs/rules/security.md) in every change. [docs/architecture.md](docs/architecture.md) is the one description of how Whytide is built.
3. Open a merge request against `main` with the template's questions answered and a changeset under `.changeset/`. A module owner reviews and squash-merges; the security-sensitive paths take two reviews.

Report a vulnerability privately, never in an issue or a merge request (docs/rules/security.md §8).
